# Modern EMCN ownership

This package owns shared controls and foundations from the new Platform UI. Read `README.md` for public imports, CSS entry points and surface ownership. `@sim/emcn-legacy` is a separate runtime for unreplaced routes; never import or re-export it here or in the Auth, Docs or Platform packages.

**EMCN is frozen.** `@sim/emcn` and `@sim/emcn-platform` change only by the design owner (`@emir-karabeg` in CODEOWNERS): compose what exists, and add no export, prop, variant, class or icon. `bun run check:emcn-surface` holds the surface to `scripts/emcn-surface.json`, which only the design owner regenerates. A part a second feature needs moves to the nearest shared product owner (`apps/sim/app/(product)/_components/`). The rules below describe how the frozen components behave, for the design owner's changes and for reading them.

- Use public family imports across packages and `#emcn` private imports inside this package. A family owns its component, CSS Module and private helpers. A barrel groups several public exports; it is not a wrapper around every file.
- Field pickers retain bordered chrome for labeled forms. Immediate preferences, table roles and toolbar filters use compact quiet text triggers without a chevron; specialized searchable, multiple-value and date-range pickers compose that same Button through their text presentation.
- Buttons that open destructive confirmations and destructive menu rows use the same `destructive` semantic prop and quiet feedback recipe. Focus alone keeps resting paint; final confirmations keep the solid destructive variant. Close, clear and dismiss × actions retain neutral hover.
- Avatar frames keep their named sizes; fallback initials align by font cap metrics without moving the outer frame.
- Explain non-obvious disabled choices and actions through optional `disabledReason`, including protected membership, inherited roles and unavailable prerequisites. Button, Checkbox and pickers use the shared tooltip with a named keyboard target while retaining disabled behavior. DataTable forwards each row's `selectionDisabledReason`; the feature owns the policy and explanation. Ordinary pending or unchanged forms need no redundant tooltip.
- Shared primitive behavior belongs here. Surface compositions belong in `emcn-auth`, `emcn-docs` or `emcn-platform`; route/data/fixture logic belongs in apps.
- Follow the existing Platform recipes. Components own their chrome and expose supported semantic states through props. Consumers do not override control paint or geometry. Use Base UI for keyboard, floating and dismissal behavior; preserve native form/link semantics and forward trigger refs and props.
- `styles/global.css` is the public shared foundation. It imports generated token/type sources and component roles, scoped to `[data-emcn]`. Surface entries import it and own their scoped aliases. Resets belong in a base layer; composition gaps belong to the parent flex/grid container. Keep standalone preflight outside the package entry.
- Keep Geist assets here and load them through the host adapter. CSS faces use unique EMCN names to avoid changing legacy pages after navigation.
- Focus follows the owning surface contract: Auth/Docs preserve the resting recipe, and Platform retains its existing keyboard-focus treatment; retain caret, selection, validation, active menu rows and the established quiet-search underline. Overflow fades reflect actual hidden content. Motion and feedback use shared timing and reduced-motion policy.
- The design owner edits generated foundations, icons and recipes at their compiler or source, never the output. Do not invent Paper counterpart keys.
- Verify actual production routes and packaged Electron consumers, not just a specimen. Run package type-check, the design/CSS guards, and affected browser checks. Use the test-audit skill for tests. Update tracked ownership when a component moves.
