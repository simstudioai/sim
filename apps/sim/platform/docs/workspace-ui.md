# Workspace UI

Open [a workspace](http://localhost:3125/workspace/it/dashboards?state=full) on a fixture-enabled Platform server. A workspace row in the sidebar, a command-search result and a workspace in the chat panel all open the workspace's Dashboard. The organization sidebar stays as it is and marks the workspace's row current, as it marks Integrations; only the page on the right changes.

| Route under `/workspace/[workspaceId]` | UI owner |
| --- | --- |
| The workspace itself | Redirects to `dashboards`. |
| `dashboards` | The workspace's read-only production snapshot: metric groups, charts, a text summary, an agent roster and typed tables. |
| `issues`, `issues/[issueId]` | Agent-proposed issues in four groups, and an issue's proposal, impact and evidence with decisions in its control bar. |
| `changelog`, `changelog/[entryId]` | Applied changes by day, and a change's details with the workspace items it touched. |
| `logs`, `logs/[runId]` | Runs with filters and sort, and a run's trace, selected step and payloads. |

These are the workspace pages Paper has. A workspace has no chat, skills, resource or workflow page here: chats belong to the organization, and the composer's slash offers skills.

## Workspace pages

Dashboard, Issues, Changelog and Logs are one family of Platform pages, styled from Home and Integrations. [Dashboard](http://localhost:3125/workspace/it/dashboards?state=full), [Issues](http://localhost:3125/workspace/it/issues?state=full), [Changelog](http://localhost:3125/workspace/it/changelog?state=full) and [Logs](http://localhost:3125/workspace/it/logs?state=full) open on any fixture workspace; `?state=stress` exercises the extremes and `?state=empty` every empty state.

- **Frame.** `WorkspacePage` puts the workspace name and description in the Integrations heading, the four pages in DestinationTabs and the tab's ControlBar beneath them, at the same positions as the integration center. Issues' search field fills the bar's leading edge; elsewhere the choices lead, each at its text width as Home's period is. Logs has no search: its status, trigger and workflow choices lead and sort ends the bar. Like Home's controls, the bar's surfaces stay inside the column and their text is inset, so a leading choice lines up with the tab labels above it. The page is at least the viewport tall, so an empty state centers in the space below the controls.
- **Rows.** Lists follow Paper's rows and the shared recipes. Issue groups take Integrations' group title with a chevron; an issue row is a caption ID, a one-line title and a right-aligned date (IssueRow). Log rows put duration, Compute Units and start time on the right (RunRow). Changelog entries take ActivityRow's title, detail and meta roles in Paper's ChangeEntry order: title and time, the description, then the contributor with the ticket at the end of the row, under the time. The dashboard's typed table is EMCN DataTable.
- **Details.** `DetailSplit` is shared by issue, change and run details: Paper's ticket bar puts the Integrations Back chip and the record's actions on one row, and a record's identifiers (an issue's ID, a run's execution ID) are among its facts. A reading column scrolls with its edge fade beside a rail with a 24px inset; the rail's hairline boundary spans only its content, extending the same 8px above and below it. Issue and change details use a 280px facts rail. Run details keep the run's metadata fields and trace in the reading column and give the rail to the selected step: its facts, then input and output in Paper's trace-payload form with the chat tool payload's monospace. Metadata fields share columns from row to row and clamp each value to one line, with the full value on hover. The trace follows Paper's TraceRow: every row, the root included, has a disclosure slot, the step's mark and its name one 8px gap apart; each level indents by one disclosure, and a hairline guide (the conversation rule) hangs under each open parent's disclosure through its last descendant, as trace views in Braintrust and Vercel draw them. A payload renders one source line at a time, so a wrapped value keeps its indent with a further 16px hang, and shows its first 32 lines until the reader asks for all of them. Below a 45rem frame the record stacks and scrolls as one: facts above the reading column, an inspector below it. Record headings and section titles match Integrations' details (DirectoryHeading, T093). Decisions use the secondary compact Button, as Connect does.
- **URL state.** Issues' search, the filters, sort and period live in the URL through nuqs (`lib/workspace-views.ts`). A row carries its list's view into the record's URL, so the Back chip returns to the same filtered, sorted list.
- **Reading position.** A list remembers its scroll position when a click leaves it. Browser Back and Forward and the record's Back chip restore it; a tab or sidebar visit starts at the top. The router renders a history step inside the popstate dispatch and scrolls a link's destination into view itself, so the page restores on the next frame and marks the shell's scroller so the shell does not reset it.
- **Paging.** Lists reveal records in pages as the reader nears the end, with no label, spinner or end marker; the shell's edge fade shows content continues. A revealed count survives Back.
- **Refresh.** Pages refresh themselves; there is no refresh control. Dashboard and Changelog say when their data last updated, and new runs join Logs as they arrive. Example time is fixed, so on fixtures the update age and the list hold still; live data will refetch in the background through the adapters.
- **Session.** Example decisions on issues change only the browser session (`workspace-session/`). Nothing is sent or stored.
- **Data.** Each route is a server component that loads server-gated fixtures and passes `data` to a client route, which supplies `actions` from the session. A live workspace row opens the authorized legacy workspace, and live Dashboard, Changelog and Logs URLs redirect there until an adapter maps the existing hooks onto the same props. Issues has no backend, so its live URLs answer 404. See the [parity ledger](org-parity.md#workspace-pages).
