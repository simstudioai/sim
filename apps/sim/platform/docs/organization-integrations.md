# Member integrations

The organization sidebar opens `/integrations`. This is the signed-in member’s Search integrations inventory. Each row opens `/integrations/[providerId]` to show the provider description, personal credential, and available actions. The index groups connected accounts, apps available to connect, and sources managed by the organization. Each row uses the workspace catalog description. Search matches provider names, descriptions and the viewer’s credential label. Selecting a result preserves the current search on return. Clearing the search and immediately opening a result still opens that provider. Browser history and sidebar navigation restore the filter from their destination URL. The browser and Sim Desktop share these routes.

The existing [organization route](../../app/o/%5BorganizationId%5D/integrations/page.tsx) requires member-scoped Search access. Its [member inventory](../../app/o/%5BorganizationId%5D/integrations/utils.ts) considers source approval, provider availability, effective organization configuration, and the viewer’s existing accounts. Existing credentials can remain visible after approval changes. Some configured Assistant apps can appear when the viewer is eligible. Generic Secrets appears only when enabled. Organization approval and source setup belong to the separate [Sources settings route](../../lib/sim-search/setup-navigation.ts).

| Member interaction | Contract for Phase 3 |
| --- | --- |
| Find a provider | Accept a server projection of visible member integrations. The inventory supplies readiness, reason, personal accounts, usable connection targets and eligible reconnects. A managed source such as GitLab has no personal login. [Inventory rules](../../app/o/%5BorganizationId%5D/integrations/utils.ts) |
| Connect, reconnect or disconnect a personal account | The Platform models one personal credential per integration. Connect uses the inline Home Email and Calendar prompt. Reconnect and disconnect act on that credential. [Account contracts](../../lib/api/contracts/organization-accounts.ts) |
| Manage tool permissions | Only projected eligible credentials receive tool controls. Read and write tools have group policies and individual overrides. Automatic approval additionally depends on account status and the viewer’s permission group. [Permission contract](../../lib/api/contracts/assistant-actions.ts) · [Permission operation](../../lib/assistant-actions/application/tool-permissions.ts) |
| Inspect Generic Secrets | An organization-managed source exposes its mode. A personal source exposes only the signed-in member’s key names. [Secret contracts](../../lib/api/contracts/organization-secrets.ts) |

With `SIM_PLATFORM_FIXTURES=1`, open [the populated inventory](http://localhost:3100/integrations?state=full), [the empty state](http://localhost:3100/integrations?state=empty), or [the stress scenario](http://localhost:3100/integrations?state=stress). The flagged loader supplies sample credential handoffs and tool catalogs. Changes live in the current product session. The default-off route has no example providers or credentials. Real authorization, credential exchange, policy persistence and secret handling belong to Phase 3.

The detail header places the provider mark beside its name and description. **Connected credential** is a separate section below the header. Its title uses the Home section heading typography and aligns with the left edge of the permissions sections. The member’s account label sits on the next line. Its trailing menu acts on that credential. A status appears when the account needs reconnection or its organization has restricted access. In the inline connection prompt, the book icon and **Docs** link sit to the left of the connect action and open the provider’s Sim Search setup guide in a new tab. Providers without a dedicated guide use the member account connection guide.

Provider names and descriptions come from Sim’s workspace integration catalog, which is generated from block definitions. Lucid uses its managed connector definition. **Tool permissions** groups eligible actions by read and write. Each tool retains its own description and approval control. **Requested permissions** lists human-readable OAuth scopes in always-visible groups. These are authorization requests. **Search access** describes the content a member can search. For managed providers such as Fireflies it lists the read-only Search operations the existing adapter supports. Use hanging bullets for static scopes and Search capabilities so wrapped lines stay with their item. Editable tool rows keep the name, description and permission control together without bullets. Actual account grants and eligible assistant tools come from their own operations. Refresh canonical metadata with `bun scripts/sync-platform-integration-metadata.ts` when its sources change.
