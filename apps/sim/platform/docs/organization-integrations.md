# Member integrations

The organization sidebar opens `/integrations`. This is the signed-in member’s Search integrations inventory. Each row opens `/integrations/[providerId]` to show the provider description, personal credential, and available actions. The index groups connected accounts, apps available to connect, and sources managed by the organization. Search matches provider names and the viewer’s own account labels. The browser and Sim Desktop share these routes.

The existing [organization route](../../app/o/%5BorganizationId%5D/integrations/page.tsx) requires member-scoped Search access. Its [member inventory](../../app/o/%5BorganizationId%5D/integrations/utils.ts) considers source approval, provider availability, effective organization configuration, and the viewer’s existing accounts. Existing credentials can remain visible after approval changes. Some configured Assistant apps can appear when the viewer is eligible. Generic Secrets appears only when enabled. Organization approval and source setup belong to the separate [Sources settings route](../../lib/sim-search/setup-navigation.ts).

| Member interaction | Contract for Phase 3 |
| --- | --- |
| Find a provider | Accept a server projection of visible member integrations. The inventory supplies readiness, reason, personal accounts, usable connection targets and eligible reconnects. A managed source such as GitLab has no personal login. [Inventory rules](../../app/o/%5BorganizationId%5D/integrations/utils.ts) |
| Connect, reconnect or disconnect a personal account | The default is one credential per member for an OAuth provider option or managed MCP server. The member sees their existing credential directly. Connect uses the same inline provider prompt as Home Email and Calendar. Only a real, unused authorized slot permits another connection. [Account contracts](../../lib/api/contracts/organization-accounts.ts) |
| Manage tool permissions | Only projected eligible credentials receive tool controls. Read and write tools have group policies and individual overrides. Automatic approval additionally depends on account status and the viewer’s permission group. [Permission contract](../../lib/api/contracts/assistant-actions.ts) · [Permission operation](../../lib/assistant-actions/application/tool-permissions.ts) |
| Inspect Generic Secrets | An organization-managed source exposes its mode. A personal source exposes only the signed-in member’s key names. [Secret contracts](../../lib/api/contracts/organization-secrets.ts) |

With `SIM_PLATFORM_FIXTURES=1`, open [the populated inventory](http://localhost:3100/integrations?state=full), [the empty state](http://localhost:3100/integrations?state=empty), or [the stress scenario](http://localhost:3100/integrations?state=stress). The flagged loader supplies sample credential handoffs and tool catalogs. Changes live in the current product session. The default-off route has no example providers or credentials. Real authorization, credential exchange, policy persistence and secret handling belong to Phase 3.

Provider names and descriptions come from Sim’s workspace integration catalog, which is generated from block definitions. Lucid uses its managed connector definition. The separate **Requested permissions** disclosure lists known provider sign-in scopes. These are the defaults requested during authorization. Account-specific grants and eligible assistant tools come from their own operations. Refresh canonical metadata with `bun scripts/sync-platform-integration-metadata.ts` when its sources change.
