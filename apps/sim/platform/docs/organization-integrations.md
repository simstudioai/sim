# Organization integrations

The sidebar and Command K open `/integrations`. Each configured provider has a detail route at `/integrations/[providerId]`. Admins manage workflow credential grants at `/integrations/access`. The browser and Electron use the same routes. Add, remove, source edits, grant edits and personal tool choices live in the current product session.

On the running Platform with `SIM_PLATFORM_FIXTURES=1`, use [the admin view](http://localhost:3100/integrations?state=full), [the member view](http://localhost:3100/integrations?state=full&role=member), [an empty organization](http://localhost:3100/integrations?state=empty) or [the full catalog](http://localhost:3100/integrations?state=stress). The role query chooses a fixture projection. The default-off server loader returns no organization, catalog, or sample accounts without the flag.

| Interaction | Existing domain owner for Phase 3 |
| --- | --- |
| Discover and add an app | Combine the organization's available account methods with its available live Search modes. Respect the deployment and viewer's permission group. [Account contracts](../../lib/api/contracts/organization-accounts.ts) · [Live Search capabilities](../../lib/sim-search/live/provider-catalog.ts) |
| Approve Search and configure sources | Approval, member sign-in, source readiness, and a person's actual connection are separate states. GitHub and GitLab use individual repository/project sources. Other service modes select a valid source for the provider. Disabling Search preserves account connections. [Approval operation](../../lib/knowledge/application/search-integrations.ts) · [Source contracts](../../lib/api/contracts/knowledge/connectors.ts) · [GitLab permissions](../../lib/api/contracts/knowledge/gitlab-permissions.ts) |
| Manage an account | OAuth, managed MCP, Slack installation, and Databricks setup each have their own handoff. Only a completed provider callback can create a connected account or finish a reconnect. [Organization account operations](../../lib/credential-groups/application/organization-accounts.ts) · [Managed MCP](../../lib/credential-groups/managed-mcp-connectors.ts) |
| Invite or revoke people | An enrollment belongs to the organization account group and can apply across providers. Invitations remain drafts until a real delivery operation runs. [Enrollment contracts](../../lib/api/contracts/organization-accounts.ts) |
| Control assistant tools | The signed-in person controls their own eligible OAuth account's read/write defaults and individual tool overrides. Automatic approval additionally requires the permission-group capability. [Tool permission operations](../../lib/assistant-actions/application/tool-permissions.ts) |
| Share credentials with workflows | Each workspace has no grant, an all-types grant, or an explicit set of credential types. OAuth and MCP remain separate types for the same vendor. Persist a change using the server revision and reload on conflict. [Workspace grant schema](../../lib/credential-groups/workspace-grants.ts) · [Organization access operations](../../lib/credential-groups/application/organization-access.ts) |

The route uses EMCN ActivityRow, Icon, DestinationTabs, SettingsSection, Modal and the shared form/menu controls. Brand artwork comes from the existing shared icon masters and local provider SVG assets. Sample providers, accounts, sources, people and grants enter exclusively through the server fixture loader. Phase 3 must replace this projection with authorized reads and mutations. OAuth, invitation delivery and secret handling stay at the server boundary.
