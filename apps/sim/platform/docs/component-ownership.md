# Choosing a Platform component

Modern shared owners live in `packages/emcn/src/components/<family>` and use `@sim/emcn/<family>` imports. Platform-specific compositions live in `packages/emcn-platform`, including ComposerInput, ConnectionPrompt, DestinationTabs, ExecutionSteps, MessageBubble, PageColumn, RecentItems, PlatformSurface, RecipientField and WorkspaceList. They consume Shared owners rather than retaining a second control implementation. Auth and Docs use the same Shared foundations and own their distinct compositions in their surface packages. Legacy components remain in `@sim/emcn-legacy` and cannot enter any new EMCN package.

Start with the interaction. A different label, icon, data source, theme or screen width rarely needs a new component. A different keyboard contract can require a different interactive element even when two surfaces have identical geometry.

| Interaction | Owner and use |
| --- | --- |
| Perform an action | `button/`: Button owns labeled actions and leading/trailing icons; IconButton owns icon-only actions and its few target sizes. Notification triggers reuse the compact secondary button; thread and notification counts share one label/count layout. CopyButton adds clipboard feedback to IconButton. Menu, popover and range triggers render these same buttons, with Base UI supplying behavior. |
| Navigate or select a row | ControlRow renders the actual link, tab or button. Chip, IdentityButton, sidebar, recent-items, destination-tabs, tabs and workspace-list compose it. A trailing ellipsis/close or a leading remove share a sibling action target: never nest a second button inside the first. A row’s read-only state goes in its `status` slot. Activity sits beside the action on touch. A pin occupies the trailing action slot until hover or menu opening reveals the ellipsis; tapping the pin opens its menu. Workspace choices can wrap to fit their name. |
| Open a two-line activity or destination | ActivityRow owns the text stack, top-aligned single or stacked leading art, hit area and mutually exclusive trailing text or people. Navigating rows end with their chevron; they have no sibling action slot. Record actions belong in details. Home email and attention, the notification inbox and the chat panel launcher supply data. A notification with independent action buttons composes the same noninteractive ActivityBody alongside its actions. Section titles and scroll bounds stay with the containing feature. |
| Choose a value or run a command | Picker owns Select, SearchableSelect (client filtering, or server search through `search`), MultiSelect, and calendar choices through DatePicker and DateRangePicker; `Calendar` stays private to it. Menu owns actions, nested menus and popovers. ChoiceMenu owns compact toolbar choices, immediate preferences and table roles, including Home ranges and integration filters, with the same quiet button and radio-menu rows. Select remains the bordered owner for labeled form fields. SearchableSelect and MultiSelect use their text presentation outside forms; DateRangePicker always uses a compact text trigger. They compose the same quiet Button without a chevron while retaining their search, multiple-selection and calendar behavior. These share popup and row recipes; retain their distinct ARIA roles and keyboard behavior. CommandPalette owns multi-group search and navigation inside the shared dialog. |
| Edit or toggle | Field owns labeled input/textarea chrome, hints and errors, including Input/TextField and TextArea/TextAreaField `viewOnly` with always-visible copy, and the CopyField adapter, SecretField (masked entry with reveal) and FileField (choose or drop; the caller reads the file). Platform globals disable manual textarea resizing. SearchField/MenuSearchField own clearable search and filtering; quiet page search has only a hover/focus underline. Field owns required placeholder contracts and the textarea sizing/chrome also used by WorkspaceFields. WorkspaceFields owns recipient parsing, editing, validation (controlled through `recipients` and `validate`), removal and logo upload. RecipientTag pairs a bounded address with an always-visible inline IconButton. The field wraps tags as a unit. ComposerInput owns native draft typing, inline reference marks, paste and submission. Its caret-anchored suggestion list keeps keyboard focus in the editor. Reference labels inherit the draft’s regular body typography and use the Platform secondary text color in both themes. A small gap separates each glyph from its label. The shell composer supplies workspace resources for `+` and `@`, integrations for `@`, and skills and available MCP servers for `/`. Local uploads remain attachments. Switch owns a setting that applies at once, Checkbox owns a boolean in a form or grid, SegmentedControl owns mutually exclusive choices. |
| Display layers and transient feedback | Modal owns title, body, multi-step progression and footer, including the optional typed footerStartAction and safe pending/focus behavior. OverlayDialog supplies the same surface to search and attachment previews. Tooltip owns bounded plain labels; a structured people panel uses its own measured content. Feedback owns clipboard success and timeout behavior. Status owns StatusTag, a read-only state on a row, InlineNotice, a persistent message in the page flow with an optional action, and FailureNotice, a failed read with its retry; a transient outcome still goes to the tray. The notification tray owns history and Undo, with one control shadow outside the scroll viewport. |
| Show files, people and media | Attachments composes ControlRow with file glyph or thumbnail, an accessible preview target and an independent quiet remove action. Avatar owns image and single-initial fallbacks across profiles, email and people details. Stack owns up to three compact overlapping pieces of artwork, name tooltips, individual hover movement and passive compact +N counts; AvatarGroup adapts people for integration usage and calendar attendees. Icon owns interface paint and distinguishes branded artwork. Product callers supply media or data. |
| Read or inspect data | Chart owns shared numerical formatting, point inspection and chart tooltips; BarChart stacks up to six layers, each keeping its color by position. DataDisplay owns metrics and table semantics: DataTable takes custom cells (TableLabel is a name with its leading mark and an optional compact detail that keeps a hidden email column readable), a whole-row target, a sibling row action, controlled sort and selection, select-all through shared Checkbox, stable fluid columns and a reserved action lane across empty and populated states, natural text wrapping within the available width, ContentTabs with an optional actions slot, and one persistent toolbar with leading search controls, trailing filter and sort controls and selection actions revealed immediately before it, paging and windowing through `@tanstack/react-virtual`. Pagination owns explicit page steps; ScrollArea's LoadMoreFooter owns reaching the end of a paged list, for tables and pickers alike. PropertyList owns labeled values with content-sized responsive label tracks and an 8px gap, without a forced minimum label width, plus inline person avatars and normal value ink, ExecutionSteps is a noninteractive numbered plan, and EmptyState describes absent data, with an optional decorative graphic. Calendar hours/events, Home activity chart axes and chat tool payloads remain with the features that interpret them. |
| Disclose and scroll | Disclosure owns keyboard-accessible expansion; tool input/output have their own disclosure content and reading rules. ScrollArea/useScrollEdges measure the actual viewport. OverflowText handles clipped text, and touch-target and layout owners handle interaction bounds and composition. PlatformSurface owns theme selection. PageColumn owns the common reading width and responsive gutters; PageOverflow owns its 8px surface overhang without introducing a theme boundary. |

FieldFrame and fieldDescription live in `packages/emcn/src/components/field/frame.tsx`, exposed with the field controls through the `@sim/emcn/field` family barrel. Its labelRender slot lets Select and Combobox own their focus-only labels inside the corresponding Base UI root. Native text inputs keep native labels. DatePicker uses a noninteractive caption associated with the trigger and visible date value through aria-labelledby. SearchableSelect and MultiSelect expose the selected value or count through aria-describedby, alongside field hints and errors. Clicking a picker caption must dismiss an open popup without synthesizing another trigger activation.

Disabled explanations use the shared Tooltip through Button, Checkbox and picker `disabledReason` props. DataTable forwards `selectionDisabledReason` to each protected row's checkbox and explains an unavailable select-all control. The feature supplies the actual policy reason. CredentialAccess reuses its inherited-access and last-administrator reasons for selection, role and removal controls; CredentialInvite explains an exhausted people list. The tooltip remains reachable by keyboard without making a disabled action operable or changing table geometry.

Routes compose these owners. The shell owns navigation, window chrome, session state and the shared message composer. Home owns the arrangement of widgets, calendar and chart. `(shell)/_components/chat/` owns turns, tool payloads, interaction cards, panel contents and resources, which Chat and Search share; `(shell)/_components/search/` owns search results. SettingsRow takes a leading avatar or glyph. Settings owns profile, appearance, notification preferences and their section layout; each live section owns one folder under `settings/_components/sections/`, and `settings/_components/section-parts/` owns what they share: the layout, sub-view header, loading rows, saved-preference rows and the credits dialog. An editor registers with `useSettingsUnsavedGuard`; `session-state/settings-leave-guard` is the one dialog, and the one owner of link and browser-history guarding. `app/_components/shell-gate/` owns the states that replace a route or the whole shell: access denied, unavailable, error and not found. `lib/data/` owns everything real data needs: the mode, the organization surface, query and session providers, and the adapters from contract shapes to view models. Product code uses no fixture fallback. The workbench and its Paper specimens are engineering tools; gallery examples do not justify product variants.

Organization integrations and workspace skills share the page frame, heading, back link and grouped list in `(shell)/_components/resource-directory`. Each directory composes EMCN SearchField, ChoiceMenu, ActivityRow and Icon. Workspace Integrations links and former workspace integration routes resolve to the organization integration center. Skills has its own list and editor. Workspace examples and edits live in the fixture session. Live workspace routes retain the existing workspace access boundary.

Member integrations use ActivityRow links, the shared Icon for provider marks, and shared segmented controls for individual tool permissions, and the same inline ConnectionPrompt as Home Email and Calendar. Its [member inventory contract](organization-integrations.md) covers personal credentials, eligible tool policies and the Phase 3 handoff.

The [Platform time library](../lib/time.ts) formats raw instants, calendar days and elapsed metadata for every feature. Home owns its Build/Search metric and a single selected time window.

For a proposed addition, trace its second consumer before copying a hit area, hover, menu, timer or modal part. A new shared visual variant requires two independent product consumers; repeating a sample row or adding a workbench example does not count. Promote the original when semantics match, and verify both callers with a pointer and keyboard. For different semantics, share the visual recipe and preserve the proper native element. Keep one-feature anatomy in its route owner and choose its spacing and type from the closest existing composition.

The [integration center](integration-center.md) lives in `integrations/_components/integration-center/` at the organization root. Its Apps, Skills, MCPs and Credentials destinations compose DestinationTabs, the shared search control and ActivityRow. The local `resource-list/` owner renders destinations. `resource-details/` owns full-page Skill/MCP creation and editing with Details/Access tabs; `resource-fields/` shares drafts, validation and fields with contextual `resource-editor/` modals. Saved suggested skills resolve their existing record by catalog source identity and retain editable fields. They do not own another button, menu, tab, form-field or dialog recipe. Personal and shared data use the same renderer. Eligible workspace entry points open or redirect to this organization center; they do not mount a separate Platform integration page. Standalone workspaces and viewers without organization Search access retain their existing credential route.

ControlBar (`(shell)/_components/control-bar`) owns the compact control row beneath a page's heading or tabs, shared by the integration center, app details and the workspace pages: an optional leading search or primary choice, then filters, sort, status text and actions at the trailing edge. CredentialList, CredentialDetail, CredentialAccess, CredentialInvite and CredentialConnect own credential-specific composition. CredentialDetail composes ContentTabs for Details, Access and applicable Permissions, with direct credential actions beside the tabs instead of a separate ellipsis row. CredentialAccess composes DataTable with People/Invitations tabs, search/filter/sort and protected bulk actions; CredentialInvite selects eligible people and a role. The feature owns access policy and metadata, while EMCN owns table/control geometry; provider setup fields come from generated metadata. The Slack bot owner retains its distinct staged setup. PeopleSentence owns the centered inline photo/name/punctuation recipe shared by app “Used by” summaries and resource “Made by” attribution. Caption text centers on its font cap metrics while preserving the original line box, and Avatar centers fallback initials within its unchanged frame; people-summary owns the common list formatting. IntegrationCapabilities owns editable suggested Skills and the complete Agent template list in the page flow. IntegrationIdea centers a selectable provider-specific MessageBubble over the full-width monochrome meeting illustration; ComposerHost prepares the Home draft without sending and requests focus after its composer mounts. Agent templates use the same handoff. ProviderHeading stays a two-part title/description, with usage and app actions in ControlBar. Each composes EMCN controls and uses the same row and section rhythm as Home and Settings.

Organization Settings uses the [navigation catalog](../lib/data/settings-navigation.ts) for sidebar order and server-gated resolution. The [section registry](../app/%28shell%29/settings/_components/section-registry.ts) lazy-loads one owner per tab. General composes Profile, Preferences, Privacy and Account, including their detail views. Section titles and action rows use EMCN SettingsSection and SettingsRow.

MessageBubble owns user-message paint and the selectable integration example, with the same radius, padding and typography. Selectable previews use two visible lines and the existing floating glass fill/blur without a border or top-edge highlight, with neutral hover/press states; ordinary chat messages retain their full content. Chat responses and formatted skill instructions use the shared MarkdownContent renderer under `(shell)/_components/markdown-content`.

Modal form items share the field family. FileField owns full-width file selection and compact image preview/removal; DetailsField labels static information; ListField owns grouped bullet lists capped at 192px or 30dvh. RecipientField retains its existing workspace-fields source path and is the shared recipient owner. ConnectionAccess only projects provider permission groups into ListField. Request dialogs compose DetailsField, and the obsolete RequestText and LogoUploadField implementations are removed. DataTable supports genuine tabular modal content without a separate modal table variant.

ManualCredentialDetail adapts metadata-only secret records into CredentialDetail and CredentialAccess, preserving one details/access interface. ResourceEditor creates manual secrets through ManualSecretFields; value replacement uses the same fields. Credentials created this way keep only key, type, provider association and explicit member metadata.

The workspace's own pages live under `workspace/[workspaceId]/`. Its `_components/` holds what they share: WorkspacePage composes DirectoryHeading, DestinationTabs and the ControlBar slot into the tab frame and centers WorkspaceEmpty in the space beneath; DetailSplit owns a record's Back link, pinned controls, scrolling reading column and 280px facts rail; DashboardTable is the read-only typed table that Dashboard and issue evidence share; WorkspaceChanges lists the workspace items a change touched with ActivityRow; RefreshStatus pairs the last update with a refresh; ListEnd asks for more near a list's end with no label. `workspace-session/` holds the view models, value formatters and the session that keeps fixture decisions, refreshes, revealed pages and each list's reading position for Back. Each tab composes these with EMCN: Dashboard renders TrendChart, BarChart, DonutChart and MetricGroup and keeps its grouped and signed bars, roster and text locally; Issues owns its grouped rows, document change, comparison and source excerpt; Logs owns its run rows, trace tree and step inspector.
