# Choosing a Platform component

Start with the interaction. A different label, icon, data source, theme or screen width rarely needs a new component. A different keyboard contract can require a different interactive element even when two surfaces have identical geometry.

| Interaction | Owner and use |
| --- | --- |
| Perform an action | `button/`: Button owns labeled actions and leading/trailing icons; IconButton owns icon-only actions and its few target sizes. CopyButton adds clipboard feedback to IconButton. Menu, popover and range triggers render these same buttons, with Base UI supplying behavior. |
| Navigate or select a row | ControlRow renders the actual link, tab or button. Chip, IdentityButton, sidebar, recent-items, destination-tabs, tabs and workspace-list compose it. A trailing ellipsis/close or a leading remove share a sibling action target: never nest a second button inside the first. Workspace choices can wrap to fit their name. |
| Open a two-line activity or destination | ActivityRow owns the text stack, leading art, hit area and optional trailing content. Home email and attention, the notification inbox and the chat panel launcher supply data. Section titles and scroll bounds stay with the containing feature. |
| Choose a value or run a command | Picker owns Select/Combobox behavior, Menu owns actions, nested menus, popovers and date range choices. These share popup and row recipes; retain their distinct ARIA roles and keyboard behavior. CommandPalette owns multi-group search and navigation inside the shared dialog. |
| Edit or toggle | Field owns labeled input/textarea chrome and errors. Platform globals disable manual textarea resizing. SearchField/MenuSearchField own clearable search and filtering. WorkspaceFields owns recipient/removal and upload behavior. ComposerInput owns draft typing, paste and submission. Switch owns a boolean, SegmentedControl owns mutually exclusive choices. |
| Display layers and transient feedback | Modal owns title, body, multi-step progression and footer. OverlayDialog supplies the same surface to search, event details and attachment previews. Tooltip owns bounded plain labels; a structured people panel uses its own measured content. Feedback owns clipboard success and timeout behavior. The notification tray owns history and Undo. |
| Show files, people and media | Attachments composes ControlRow with file glyph or thumbnail, an accessible preview target and an independent destructive remove action. Avatar owns image and single-initial fallbacks across profiles, email and people details. Icon owns interface paint and distinguishes branded artwork. Product callers supply media or data. |
| Read or inspect data | Chart owns shared numerical formatting, point inspection and chart tooltips. DataDisplay owns metrics and table semantics; PropertyList owns labeled values, ExecutionSteps is a noninteractive numbered plan, and EmptyState describes absent data. Calendar hours/events, task-chart axes and chat tool payloads remain with the features that interpret them. |
| Disclose and scroll | Disclosure owns keyboard-accessible expansion; tool input/output have their own disclosure content and reading rules. ScrollArea/useScrollEdges measure the actual viewport. OverflowText handles clipped text, and touch-target and layout owners handle interaction bounds and composition. PlatformSurface owns theme selection. |

Routes compose these owners. The shell owns navigation, window chrome, session state and the shared message composer. Home owns the arrangement of widgets, calendar and chart. Chat owns turns, tool payloads, panel contents and resources. Settings owns profile, appearance, notification preferences and their section layout. Product code uses no fixture fallback. The workbench and its Paper specimens are engineering tools; gallery examples do not justify product variants.

For a proposed addition, trace its second consumer before copying a hit area, hover, menu, timer or modal part. Promote the original when semantics match, and verify both callers with a pointer and keyboard. For different semantics, share the visual recipe and preserve the proper native element.
