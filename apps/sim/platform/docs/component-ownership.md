# Choosing a Platform component

Start with the interaction. A different label, icon, data source, theme or screen width rarely needs a new component. A different keyboard contract can require a different interactive element even when two surfaces have identical geometry.

| Interaction | Owner and use |
| --- | --- |
| Perform an action | `button/`: Button owns labeled actions and leading/trailing icons; IconButton owns icon-only actions and its few target sizes. Notification triggers reuse the compact secondary button; thread and notification counts share one label/count layout. CopyButton adds clipboard feedback to IconButton. Menu, popover and range triggers render these same buttons, with Base UI supplying behavior. |
| Navigate or select a row | ControlRow renders the actual link, tab or button. Chip, IdentityButton, sidebar, recent-items, destination-tabs, tabs and workspace-list compose it. A trailing ellipsis/close or a leading remove share a sibling action target: never nest a second button inside the first. Workspace choices can wrap to fit their name. |
| Open a two-line activity or destination | ActivityRow owns the text stack, leading art, hit area and optional trailing content. Home email and attention, the notification inbox and the chat panel launcher supply data. A notification with independent action buttons composes the same noninteractive ActivityBody alongside its actions. Section titles and scroll bounds stay with the containing feature. |
| Choose a value or run a command | Picker owns Select, SearchableSelect (client filtering, or server search through `search`), MultiSelect, and calendar choices through DatePicker and DateRangePicker; `Calendar` stays private to it. Menu owns actions, nested menus, popovers and preset range choices. These share popup and row recipes; retain their distinct ARIA roles and keyboard behavior. CommandPalette owns multi-group search and navigation inside the shared dialog. |
| Edit or toggle | Field owns labeled input/textarea chrome, hints and errors, plus CopyField (read-only value with copy), SecretField (masked entry with reveal) and FileField (choose or drop; the caller reads the file). Platform globals disable manual textarea resizing. SearchField/MenuSearchField own clearable search and filtering. WorkspaceFields owns recipient parsing, editing, validation (controlled through `recipients` and `validate`), removal and logo upload. RecipientTag pairs a bounded address with an always-visible inline IconButton. The field wraps tags as a unit. ComposerInput owns draft typing, paste and submission. Switch owns a setting that applies at once, Checkbox owns a boolean in a form or grid, SegmentedControl owns mutually exclusive choices. |
| Display layers and transient feedback | Modal owns title, body, multi-step progression and footer. OverlayDialog supplies the same surface to search and attachment previews. Tooltip owns bounded plain labels; a structured people panel uses its own measured content. Feedback owns clipboard success and timeout behavior. Status owns StatusTag, a read-only state on a row, and InlineNotice, a persistent message in the page flow with an optional action; a transient outcome still goes to the tray. The notification tray owns history and Undo, with one control shadow outside the scroll viewport. |
| Show files, people and media | Attachments composes ControlRow with file glyph or thumbnail, an accessible preview target and an independent quiet remove action. Avatar owns image and single-initial fallbacks across profiles, email and people details. Icon owns interface paint and distinguishes branded artwork. Product callers supply media or data. |
| Read or inspect data | Chart owns shared numerical formatting, point inspection and chart tooltips. DataDisplay owns metrics and table semantics: DataTable takes custom cells, a whole-row target, a sibling row action, controlled sort, paging and windowing through `@tanstack/react-virtual`. Pagination owns explicit page steps; ScrollArea's LoadMoreFooter owns reaching the end of a paged list, for tables and pickers alike. PropertyList owns labeled values, ExecutionSteps is a noninteractive numbered plan, and EmptyState describes absent data, with an optional decorative graphic. Calendar hours/events, Home activity chart axes and chat tool payloads remain with the features that interpret them. |
| Disclose and scroll | Disclosure owns keyboard-accessible expansion; tool input/output have their own disclosure content and reading rules. ScrollArea/useScrollEdges measure the actual viewport. OverflowText handles clipped text, and touch-target and layout owners handle interaction bounds and composition. PlatformSurface owns theme selection. |

Routes compose these owners. The shell owns navigation, window chrome, session state and the shared message composer. Home owns the arrangement of widgets, calendar and chart. `(shell)/_components/chat/` owns turns, tool payloads, interaction cards, panel contents and resources, which Chat and Search share; `(shell)/_components/search/` owns search results. SettingsRow takes a leading avatar or glyph. Settings owns profile, appearance, notification preferences and their section layout; each live section owns one folder under `settings/_components/sections/`. `app/_components/shell-gate/` owns the states that replace a route or the whole shell: access denied, unavailable, error and not found. `lib/data/` owns everything real data needs: the mode, the organization surface, query and session providers, and the adapters from contract shapes to view models. Product code uses no fixture fallback. The workbench and its Paper specimens are engineering tools; gallery examples do not justify product variants. `/workbench/controls` exercises controls with no Paper master.

Member integrations uses ActivityRow links, the shared Icon for provider marks, and shared segmented controls for individual tool permissions, and the same inline ConnectionPrompt as Home Email and Calendar. Its [member inventory contract](organization-integrations.md) covers personal credentials, eligible tool policies and the Phase 3 handoff.

The [Platform time library](../lib/time.ts) formats raw instants, calendar days and elapsed metadata for every feature. Home owns its Build/Search metric and a single selected time window.

For a proposed addition, trace its second consumer before copying a hit area, hover, menu, timer or modal part. Promote the original when semantics match, and verify both callers with a pointer and keyboard. For different semantics, share the visual recipe and preserve the proper native element.
