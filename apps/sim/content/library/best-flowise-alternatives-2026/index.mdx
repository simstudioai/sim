Sim, n8n, Langflow, Dify, and LangGraph are production Flowise alternatives for teams moving visual AI-agent prototypes into production. Sim fits teams that want the open-source AI workspace, a visual builder, multiple production deployment options, and an [OSI-approved Apache 2.0 core](https://github.com/simstudioai/sim/blob/main/LICENSE), while modules in `apps/sim/ee` use the separate [Sim Enterprise License](https://github.com/simstudioai/sim/blob/main/apps/sim/ee/LICENSE) and require an active Enterprise subscription for production use.

## TL;DR

Flowise alternatives differ most in deployment flexibility, self-hosting, license clarity, governance, observability, and pricing predictability.

- [Flowise reached end of life on August 31, 2026](https://flowiseai.com/sunset). Its team froze the code on July 29 and stopped reviewing or accepting pull requests, so production users must maintain a permitted fork or migrate.
- **Sim**, the open-source AI workspace, fits teams that want to build agents visually, deploy them several ways, and self-host an Apache 2.0 core, with enterprise modules covered by the separate [Sim Enterprise License](https://github.com/simstudioai/sim/blob/main/apps/sim/ee/LICENSE).
- **Langflow** fits Python teams that want a visual builder under an MIT license.
- **Dify** fits teams building knowledge-base-backed AI apps for web, API, or Model Context Protocol (MCP) deployment, which lets compatible AI clients discover and call app tools.
- **n8n** fits integration-heavy business automation that includes AI agents, but its Sustainable Use License is source-available and is not OSI-approved.
- **LangGraph** fits engineers who prefer code-based control over agent behavior and persistent state.

## Key facts at a glance

This comparison favors platforms whose production path is explicit about licensing, hosting, operational controls, and recurring cost.

- **Flowise:** Flowise retains an Apache 2.0 core with enterprise-code exceptions, can still be self-hosted from existing code, and has no current official paid plan for new production use after its [August 31, 2026 sunset](https://flowiseai.com/sunset).
- **Sim:** Sim has an [Apache 2.0 core](https://github.com/simstudioai/sim/blob/main/LICENSE), supports cloud or [self-hosted deployment](https://docs.sim.ai/platform/self-hosting), and bills Sim Cloud by plan and user while separately licensing enterprise modules for production.
- **Langflow:** Langflow uses the [MIT license](https://github.com/langflow-ai/langflow/blob/main/LICENSE), supports local and remote self-hosting, and charges no software license fee for the open-source package.
- **Dify:** Dify uses a [modified Apache 2.0 license](https://github.com/langgenius/dify/blob/main/LICENSE), supports Docker Compose self-hosting, and sells hosted plans per workspace with message credits and resource limits.
- **n8n:** n8n uses a source-available [Sustainable Use License](https://docs.n8n.io/n8n-community-license), offers cloud and self-hosted editions, and bills paid plans by monthly workflow executions.
- **LangGraph:** LangGraph uses the [MIT license](https://github.com/langchain-ai/langgraph/blob/main/LICENSE), runs in developer-managed infrastructure or LangSmith deployment services, and pairs a free library with seat and usage-based LangSmith plans.

## Why Flowise teams are migrating now

Flowise teams are migrating because the company officially wound down Flowise operations and ended core-team maintenance on August 31, 2026.

Flowise's [July 29, 2026 sunset announcement](https://flowiseai.com/sunset) stopped active feature development and ended review of new pull requests. If a production deployment needs a fix, users can no longer submit a change and expect the former maintainers to merge it.

In August 2026, Flowise [archived its GitHub repository](https://github.com/FlowiseAI/Flowise/discussions/6727). As of November 2026, the code remains visible, but the repository is read-only, issues and pull requests are locked, and npm packages and Docker images are marked deprecated.

Existing deployments can continue to run, and the code covered by Apache 2.0 remains available to fork. The [Flowise repository license](https://github.com/FlowiseAI/Flowise/blob/main/LICENSE.md) excludes designated enterprise code and separately noticed files, so teams must review those boundaries before maintaining or redistributing a fork.

## How much does Flowise cost?

Flowise has no current official paid plan for new production use as of November 2026 because the company has wound down operations.

The official [sunset notice](https://flowiseai.com/sunset) says existing Cloud users were given time to export their data and that the open repository would become read-only. Existing self-hosted users can continue operating code within the [repository's license terms](https://github.com/FlowiseAI/Flowise/blob/main/LICENSE.md), but they must pay their own infrastructure and maintenance costs, and designated enterprise code remains outside the Apache 2.0 grant.

### Sim

**Best for:** Sim fits teams that want to build, deploy, and manage AI agents in one open-source AI workspace while retaining visual development, run logs, and self-hosting.

**Pricing:** As of November 2026, [Sim Cloud has four tiers](https://www.sim.ai/pricing): Free costs $0 and includes 1,000 one-time credits worth $5 with no weekly refresh; Pro costs $25 per user per month and includes 6,000 credits plus 2,000 refreshed weekly; Max costs $100 per user per month and includes 25,000 credits plus 4,000 refreshed weekly; Enterprise has custom pricing and limits. Logs are retained for 30 days on Free, while Pro and Max have no default age expiry. [Workspace bring your own key (BYOK), which lets a workspace use its own model-provider credentials, works on any Sim Cloud plan, while organization-level keys require Pro for Teams, Max for Teams, or Enterprise](https://docs.sim.ai/platform/costs#bring-your-own-key-byok).

**Strengths:** Sim combines Chat, a visual workflow builder, Tables, Files, and a Knowledge Base. The builder includes Agent, Condition, Router, and Human blocks, with the Human block pausing a run until a person submits form fields. Anyone can [self-host Sim's Apache 2.0 core with Docker Compose or Kubernetes](https://docs.sim.ai/platform/self-hosting), and any self-hosted deployment can use Ollama, vLLM, LM Studio, or LiteLLM without Enterprise. Workflows can deploy through an [API, Chat, MCP server, webhook, or schedule](https://docs.sim.ai/workflows/deployment), call tools from external MCP servers, and [deploy as tools on an MCP server](https://docs.sim.ai/workflows/deployment/mcp). [Run logs](https://docs.sim.ai/logs-debugging) show status, duration, cost, resolved inputs, outputs, errors, and timed spans, while a [Sim Workspace Events trigger](https://docs.sim.ai/workflows/triggers/sim) can start an alert workflow after a failure. Enterprise adds [audit logs](https://docs.sim.ai/platform/enterprise/audit-logs), [data drains](https://docs.sim.ai/platform/enterprise/data-drains), [permission groups](https://docs.sim.ai/platform/enterprise/access-control), and [data-retention policies](https://docs.sim.ai/platform/enterprise/data-retention). Sim documents [270+ integrations](https://www.sim.ai/pricing), and its [Flowise comparison](https://www.sim.ai/comparisons/flowise) covers the products side by side. For observability detail, see [AI observability tools for production agents](https://www.sim.ai/library/6-best-ai-observability-tools-for-production-agents-in-2026).

**Limitations:** Sim's Apache 2.0 core does not include modules governed by the Sim Enterprise License, including single sign-on (SSO), automated user provisioning through System for Cross-domain Identity Management (SCIM), access control, access requests, audit logs, data retention, data drains, workspace forking, session policies, custom blocks, and credential groups. Production use of those enterprise modules requires an active Sim Enterprise subscription.

**Sources:** [Root license](https://github.com/simstudioai/sim/blob/main/LICENSE), [enterprise license](https://github.com/simstudioai/sim/blob/main/apps/sim/ee/LICENSE), [self-hosting](https://docs.sim.ai/platform/self-hosting), [deployment](https://docs.sim.ai/workflows/deployment), [logs](https://docs.sim.ai/logs-debugging), and [pricing](https://www.sim.ai/pricing).

### Langflow

**Best for:** Langflow fits Python teams that want a visual builder, custom components, and a permissive MIT license.

**Pricing:** As of November 2026, the MIT-licensed Langflow software has no license fee for self-hosting, while operators pay infrastructure costs and can separately purchase [IBM Elite Support for Langflow](https://docs.langflow.org/luna-for-langflow).

**Strengths:** [Langflow](https://docs.langflow.org/) builds AI applications with a visual flow editor and Python components. Teams can trigger flows through an API, expose flows as [MCP tools](https://docs.langflow.org/mcp-server), and install Langflow as a desktop app, Python package, or Docker image through its [installation options](https://docs.langflow.org/get-started-installation). The [Human Input component](https://docs.langflow.org/human-in-the-loop) pauses a flow at a checkpoint and resumes along the chosen branch without rerunning completed steps. [Traces](https://docs.langflow.org/traces) record flow and component spans with status, inputs, outputs, latency, token usage, and errors.

**Limitations:** Langflow operators remain responsible for securing, scaling, updating, and backing up self-hosted deployments. Built-in authentication is available, but [role-based access control requires an authorization plugin](https://docs.langflow.org/authorization) that Langflow does not include.

**Sources:** [Documentation](https://docs.langflow.org/), [MIT license](https://github.com/langflow-ai/langflow/blob/main/LICENSE), [deployment overview](https://docs.langflow.org/deployment-overview), [MCP server](https://docs.langflow.org/mcp-server), and [traces](https://docs.langflow.org/traces).

### Dify

**Best for:** Dify fits teams that need to build and deploy knowledge-backed AI applications through a visual studio.

**Pricing:** As of November 2026, [Dify's hosted plans](https://dify.ai/pricing) include a free Sandbox plan, Professional at $59 per workspace monthly or $590 yearly, Team at $159 per workspace monthly or $1,590 yearly, and custom Enterprise pricing.

**Strengths:** [Dify centers on Workflow and Chatflow apps](https://docs.dify.ai/en/learn/key-concepts) built in a drag-and-drop studio. Its [Agent node](https://docs.dify.ai/en/cloud/use-dify/nodes/agent) supports Function Calling and ReAct strategies, and teams can [deploy an app as a web app, API, or MCP server](https://docs.dify.ai/en/cloud/use-dify/publish/README). A [Human Input node](https://docs.dify.ai/en/api-reference/guides/human-input-flow) pauses a workflow for a person's decision, while [run logs](https://docs.dify.ai/en/self-host/use-dify/monitor/logs) capture production conversations and workflow runs.

**Limitations:** Dify's [modified Apache 2.0 license](https://github.com/langgenius/dify/blob/main/LICENSE) requires a commercial license for specified multi-tenant uses and restricts removal or modification of branding in its frontend. Its [Docker Compose installation](https://docs.dify.ai/en/self-host/deploy/quick-start/docker-compose) runs multiple application and data services, which increases operational responsibility.

**Sources:** [Pricing](https://dify.ai/pricing), [license](https://github.com/langgenius/dify/blob/main/LICENSE), [key concepts](https://docs.dify.ai/en/learn/key-concepts), [deployment](https://docs.dify.ai/en/cloud/use-dify/publish/README), and [logs](https://docs.dify.ai/en/self-host/use-dify/monitor/logs).

### n8n

**Best for:** n8n fits teams whose main requirement is integration-heavy business automation with AI agents embedded in larger workflows.

**Pricing:** As of November 2026, [n8n Cloud](https://n8n.io/pricing/) Starter costs €20 per month and Pro costs €50 per month, while self-hosted Business costs €667 per month, all billed annually; the self-hosted Community edition is free, and Enterprise pricing is custom.

**Strengths:** [n8n connects applications through visual workflows](https://n8n.io/), and its AI Agent node lets agents call tools inside broader automations. n8n advertises [500+ native integrations](https://n8n.io/) while its [integrations directory](https://n8n.io/integrations/) lists 2,000+ integration pages. For higher execution volumes, [queue mode](https://docs.n8n.io/deploy/host-n8n/configure-n8n/scaling/enable-queue-mode) distributes runs across workers through Redis. Teams can also [require human approval for selected AI Agent tool calls](https://docs.n8n.io/build/integrate-ai/ai-examples/human-in-the-loop-for-tools), review execution history, and use plan-dependent RBAC and Insights.

**Limitations:** n8n's [Sustainable Use License](https://docs.n8n.io/n8n-community-license) is a fair-code, source-available license rather than an OSI-approved open-source license, and `.ee` files use the separate n8n Enterprise License. Its automation-first scope is less direct than a dedicated AI-agent workspace when teams primarily need agent prototyping, evaluation, and deployment.

**Sources:** [Pricing](https://n8n.io/pricing/), [community license guidance](https://docs.n8n.io/n8n-community-license), [repository license](https://github.com/n8n-io/n8n/blob/master/LICENSE.md), [self-hosted editions](https://docs.n8n.io/deploy/host-n8n/community-edition-features), [RBAC](https://docs.n8n.io/administer/manage-users-and-access/set-permissions-and-roles-rbac), and [execution history](https://docs.n8n.io/build/understand-workflows/understand-executions).

### LangGraph

**Best for:** LangGraph fits engineering teams that want to define durable agent behavior in code rather than in a visual builder.

**Pricing:** As of November 2026, the MIT library has no license fee, while [LangSmith](https://www.langchain.com/pricing) Developer costs $0 for one seat, Plus costs $39 per seat per month, and Enterprise pricing is custom.

**Strengths:** LangGraph builds agents as graphs of steps and decisions. Its [MIT-licensed library](https://github.com/langchain-ai/langgraph/blob/main/LICENSE) includes [checkpointers](https://docs.langchain.com/oss/python/langgraph/persistence) that persist a thread's graph state so paused work can resume. Developers can [call `interrupt()` inside a graph node](https://docs.langchain.com/oss/python/langgraph/interrupts) to pause for human input, then resume with a `Command`. Deployment choices include an application-owned API, LangSmith Cloud, BYOC, self-hosted Agent Server, and a [standalone Agent Server](https://docs.langchain.com/langsmith/deploy-standalone-server).

**Limitations:** LangGraph provides a code-first runtime rather than a visual workspace, so teams must supply more of the application, governance, and operational layer. [Self-hosted LangSmith](https://docs.langchain.com/langsmith/self-hosted) is an Enterprise add-on, and managed observability and deployment costs are separate from the free library.

**Sources:** [MIT license](https://github.com/langchain-ai/langgraph/blob/main/LICENSE), [persistence](https://docs.langchain.com/oss/python/langgraph/persistence), [interrupts](https://docs.langchain.com/oss/python/langgraph/interrupts), [deployment](https://docs.langchain.com/langsmith/deploy-overview), and [pricing](https://www.langchain.com/pricing).

## Migrating off Flowise without losing production state

Flowise migrations should start with an inventory of live traffic, durable state, credentials, and operational dependencies.

Audit request logs, webhook calls, and scheduled runs to identify which workflows receive traffic. Record owners, external connections, expected outputs, and access requirements so the replacement can be tested before cutover.

Back up Flowise's database and any stored chat or execution history that must be retained. Inventory credentials separately, confirm each secret can be re-entered securely, and rotate any credential that may have been exposed. In the replacement deployment, verify that workflows and state survive a restart, durable storage is configured, and authentication blocks unauthorized access.

Run representative production requests against the replacement, including requests that call external tools. Compare outputs, confirm logs capture failures, and keep a rollback plan until those checks pass. [Flowise's core-team presence ended on August 31, 2026](https://flowiseai.com/sunset), so migration plans should not depend on a future core-team fix.

For a detailed cutover sequence, use [Moving AI Agent Prototypes Into Production: A Practical Guide](https://www.sim.ai/library/moving-ai-agent-prototypes-into-production).
