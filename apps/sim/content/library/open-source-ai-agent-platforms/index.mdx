The best open source AI agents in 2026 depend on who builds them. Sim, the open-source AI workspace for building, deploying, and managing AI agents, is a strong fit for teams that want a visual builder and self-hosting on an Apache 2.0 core. LangGraph and CrewAI (both MIT) suit engineers who want orchestration in code. Microsoft Agent Framework (MIT) is the successor to AutoGen, which Microsoft no longer maintains.

Sim publishes this guide and is one of the products covered. Every license, star count, release, and price below was checked against the vendor's repository or pricing page on October 20, 2026, and each tool gets its limitations stated plainly, Sim included.

> **Choose a code-first framework when** developers want agent logic to live in Python or TypeScript and your team will own hosting, tracing, and access control. **Choose Dify when** document retrieval apps are the main job and its modified Apache 2.0 terms fit your use. **Choose n8n when** you are adding AI to existing automations and a source-available license is acceptable. **Choose Sim when** a mixed team needs to build agents visually, conversationally, or with code, and then deploy them as an API, a chat, or MCP tools (MCP, the Model Context Protocol, is a standard way for agents to call external tools) from one self-hostable workspace.

## What should you look for in an open source AI agent platform?

Look at the exact license first, then self-hosting, orchestration, integrations, model connectivity, team usability, and maintenance. Most "best open source AI agent" lists rank every tool on stars and model support, which hides the bigger question of what kind of tool you are looking at.

There are three kinds:

| Type | Examples | Who it fits | Core tradeoff |
|---|---|---|---|
| Code-first frameworks | LangGraph, CrewAI, Microsoft Agent Framework, AG2 | Engineering teams building custom agent logic | Maximum control, but you own the infrastructure and deployment stack |
| Visual builders | Dify, n8n | Mixed technical teams shipping quickly | Fast time to value, but license limits and a ceiling on complex logic |
| Open-source AI workspaces | Sim | Teams that need to build, deploy, and collaborate in one place | Broad built-in capability, but a younger ecosystem than the established frameworks |

Within any type, check these criteria:

- **License.** Read the core repository's license and any separately licensed enterprise directory. Source visibility alone does not guarantee modification or redistribution rights.
- **Self-hosting.** Confirm the vendor documents a supported self-hosted deployment and which capabilities need a commercial edition. Self-hosting gives more control over infrastructure, data handling, and model access.
- **Multi-step orchestration.** Production agents need dependencies, branching, parallel work, retries, and human review, not one prompt followed by one response.
- **Integrations.** Maintained connectors plus API, webhook, or custom-code escape hatches decide whether an agent can act across your existing systems.
- **Model connectivity.** Multiple hosted providers and local model servers let you balance capability, cost, latency, and data requirements.
- **Team usability.** Collaboration, access control, change review, and execution history matter once agents move beyond one developer.
- **Maintenance.** Check recent releases and the README for archive or maintenance notices. Two well-known projects in this category, AutoGen and Flowise, have stopped active development.

GitHub stars measure community attention, not quality, security, or production readiness, so they are listed for context only.

## Which open source AI agents and platforms are worth evaluating?

Eight projects are worth evaluating in October 2026, in seven entries: one AI workspace, four code-first frameworks (with Microsoft Agent Framework and AG2 grouped as AutoGen's successors), two source-available visual builders, and one coding-agent platform. Each entry follows the same order: best for, pricing, strengths, limitations, sources.

### 1. Sim

Sim is the open-source AI workspace where teams build, deploy, and manage AI agents, visually, conversationally, or with code. Frameworks give you agent logic and leave deployment, observability, collaboration, and knowledge management for you to build or buy. Sim puts those layers in one workspace: a visual workflow builder, Chat for building and managing agents in natural language, Tables, Files, and Knowledge Bases for agent context, and run logs for every execution.

**Best for:** Teams that need to move from prototype to production without stitching together a separate framework, observability tool, and deployment layer, especially when collaboration and multi-model flexibility are requirements.

**Pricing:** The Apache 2.0 core is free to self-host. On Sim Cloud, the Free plan includes 1,000 one-time credits (worth $5), Pro is $25 per user per month, and Max is $100 per user per month; Enterprise is custom.

**Strengths:**

- **Visual builder with code escape hatches:** Agent, API, function, condition, loop, and router blocks, plus 270+ integrations such as Slack, Notion, GitHub, Salesforce, and Stripe.
- **Many model providers:** Hosted models from OpenAI, Anthropic, Google, Mistral, xAI, and others, and on [self-hosted deployments](https://docs.sim.ai/platform/self-hosting) Ollama, vLLM, LM Studio, or LiteLLM endpoints without Sim Enterprise.
- **One workflow, several surfaces:** [Deploy the same workflow](https://docs.sim.ai/workflows/deployment) as a REST API, a hosted chat, or a set of MCP tools, and call external MCP servers from agents.
- **Human review built in:** A Human block pauses a run until someone submits input, and a Condition routes on the decision.
- **Real-time collaboration:** Write and Admin members edit the same workflow live, with permission controls.
- **Self-hosting:** Docker Compose or a Helm chart for Kubernetes, both running the same app, realtime service, and background job endpoints.

**Limitations:** Sim is younger than the established frameworks, and its community is smaller: its repository has about 29,900 GitHub stars against roughly 43,600 for LangGraph and 208,000 for n8n. Enterprise governance features in `apps/sim/ee`, including SSO, SCIM, access control, audit logs, and data retention, are under the [Sim Enterprise License](https://github.com/simstudioai/sim/blob/main/apps/sim/ee/LICENSE): free for development, testing, and internal non-production use, but production use requires an Enterprise subscription, and modification and redistribution are not permitted. Sim Cloud cannot reach a model server inside your network, so local models require self-hosting.

Compared with the frameworks below, Sim ships the deployment, logs, and team workspace that LangGraph and CrewAI leave you to build, at the cost of less low-level control than writing the graph in code.

**Sources:** [Sim Apache 2.0 license](https://github.com/simstudioai/sim/blob/main/LICENSE), [Sim Enterprise License](https://github.com/simstudioai/sim/blob/main/apps/sim/ee/LICENSE), [self-hosting docs](https://docs.sim.ai/platform/self-hosting), [deployment docs](https://docs.sim.ai/workflows/deployment), [BYOK and costs](https://docs.sim.ai/platform/costs#bring-your-own-key-byok), [GitHub repository](https://github.com/simstudioai/sim).

### 2. LangGraph

[LangGraph](https://github.com/langchain-ai/langgraph) is the low-level orchestration library in the LangChain ecosystem. Since LangChain 1.0, [LangChain's `create_agent` runs on LangGraph](https://docs.langchain.com/oss/python/releases/langgraph-v1), so many LangChain agents already use it underneath.

**Best for:** Teams with strong engineering resources building complex stateful agents, where explicit control over every decision branch matters more than speed to first deployment.

**Pricing:** The library is free under MIT. [LangSmith](https://www.langchain.com/pricing), the commercial tracing, evaluation, and deployment service, has a Developer plan at $0 per seat with up to 5k base traces a month, Plus at $39 per seat per month, and custom Enterprise pricing.

**Strengths:** Branching logic that defines exactly which path an agent takes based on state; durable execution with checkpointing, persistence, streaming, and human-in-the-loop as first-class features; and fine-grained control over each step. It also benefits from LangChain's large set of loaders, tools, and model clients.

**Limitations:** Setup is not trivial for teams new to graph-based agents. LangSmith is the recommended way to monitor LangGraph in production; you do not need it to run graphs, but teams that skip it must assemble their own tracing. Non-engineers cannot build or modify agents without an extra layer. Compared with Sim, LangGraph gives deeper programmatic control but no built-in visual builder, team workspace, or deployment surfaces in the open-source package.

**Sources:** [MIT license](https://github.com/langchain-ai/langgraph/blob/main/LICENSE), [LangGraph v1 release notes](https://docs.langchain.com/oss/python/releases/langgraph-v1), [LangSmith pricing](https://www.langchain.com/pricing), [Sim vs LangChain](https://www.sim.ai/comparisons/langchain).

### 3. CrewAI

[CrewAI](https://github.com/crewAIInc/crewAI) uses a mental model that is easy to pick up: instead of abstract graph nodes, you define roles. A researcher agent gathers information, a writer drafts, and a reviewer checks quality. [Flows](https://docs.crewai.com/en/concepts/flows) add "structured, event-driven workflows" that connect tasks, manage state, and control execution. A crew is the team; a flow is the project plan that coordinates several teams.

**Best for:** Teams automating multi-step work that naturally splits into role specializations, where Flows give enough orchestration to avoid building a custom control plane.

**Pricing:** The core framework is free under MIT. CrewAI's [hosted platform](https://crewai.com/pricing) has a free Basic plan that includes the visual editor, tracing, and deployment on CrewAI cloud with 50 workflow executions a month, and a custom-priced Enterprise plan that adds SSO, RBAC, workload identity, PII redaction, and policies, plus deployment in your own VPC or infrastructure.

**Strengths:** A quick path from idea to a working multi-agent prototype when work decomposes into roles; Flows for event-driven pipelines; [many model providers](https://docs.crewai.com/en/concepts/llms) including local models through Ollama; and [MCP servers as tools](https://docs.crewai.com/en/mcp/overview).

**Limitations:** CrewAI is open core. The visual editor, tracing, and managed deployment live in the hosted platform rather than the MIT framework, the free Basic plan caps you at 50 executions a month, and SSO, RBAC, and governance policies require the Enterprise tier. Sim includes a visual builder, run logs, and deployment in its Apache 2.0 core, while CrewAI keeps the core lighter and lets Python teams stay entirely in code.

**Sources:** [MIT license](https://github.com/crewAIInc/crewAI/blob/main/LICENSE), [CrewAI pricing](https://crewai.com/pricing), [Flows docs](https://docs.crewai.com/en/concepts/flows), [Sim vs CrewAI](https://www.sim.ai/comparisons/crewai), [CrewAI alternatives](/library/best-crewai-alternatives-2026).

### 4. Microsoft Agent Framework and AG2

AutoGen made conversational multi-agent systems popular, but Microsoft no longer maintains it: the [README](https://github.com/microsoft/autogen) says it is "no longer actively maintained by Microsoft," that Microsoft "is not providing bug fixes, security fixes, new features, or support," and advises against production use. Its last release, 0.7.5, shipped on September 30, 2025. Two successors remain.

[Microsoft Agent Framework](https://github.com/microsoft/agent-framework) is the official successor. Microsoft [introduced it on October 1, 2025](https://devblogs.microsoft.com/foundry/introducing-microsoft-agent-framework-the-open-source-engine-for-agentic-ai-apps/) to combine AutoGen's multi-agent patterns with Semantic Kernel's enterprise stability, and AutoGen's README calls it "the enterprise-ready successor to AutoGen" with a 1.0 production release, migration guides, and support for the A2A (agent-to-agent) protocol and MCP. [AG2](https://github.com/ag2ai/ag2) is a community project maintained by volunteers from several organizations. Since AG2 v1.0, its main package is a new framework imported as `ag2`, while the original AutoGen-derived API (`ConversableAgent`, `GroupChat`) lives on as [AG2 Classic](https://github.com/ag2ai/ag2-classic) in a separate repository.

**Best for:** Organizations in the Microsoft ecosystem (Agent Framework) and teams with existing AutoGen-style GroupChat code (AG2 Classic) that need a maintained path forward.

**Pricing:** Both are free libraries; Agent Framework is MIT and AG2 is Apache 2.0.

**Strengths:** Conversational multi-agent patterns where agents reason together, which suits research and prototyping. Agent Framework adds long-term support and multi-provider model support; AG2 Classic keeps a community-led, backward-compatible route for older code (AG2 v1.0 itself is not a drop-in upgrade).

**Limitations:** The ecosystem has fragmented, and teams must pick a branch and accept migration work. AutoGen Studio, the low-code interface, is "not meant to be a production-ready app" per [its own docs](https://microsoft.github.io/autogen/stable/user-guide/autogenstudio-user-guide/). Compared with Sim, both are libraries: Agent Framework emits OpenTelemetry traces, but the tracing backend, deployment, and team collaboration are yours to run and build.

**Sources:** [AutoGen README](https://github.com/microsoft/autogen/blob/main/README.md), [AutoGen code license (MIT)](https://github.com/microsoft/autogen/blob/main/LICENSE-CODE), [Agent Framework license (MIT)](https://github.com/microsoft/agent-framework/blob/main/LICENSE), [AG2 license (Apache 2.0)](https://github.com/ag2ai/ag2/blob/main/LICENSE), [AG2 README](https://github.com/ag2ai/ag2).

### 5. Dify (source available)

[Dify](https://github.com/langgenius/dify) is a visual builder for LLM applications and agentic workflows, from internal Q&A bots to custom assistants, with a workflow editor, built-in retrieval (RAG) pipeline management, many model providers, and the ability to [publish apps as an MCP server](https://docs.dify.ai/en/self-host/use-dify/publish/publish-mcp). With about 159,000 GitHub stars, it has the second-largest repository in this guide after n8n.

**Best for:** Teams whose main use case is document retrieval, knowledge bases, and structured Q&A, and enterprises using Dify as an LLM gateway.

**Pricing:** The self-hosted Community Edition [runs with Docker Compose](https://docs.dify.ai/en/self-host/deploy/quick-start/docker-compose). [Dify Cloud](https://dify.ai/pricing) has a free Sandbox with 200 message credits, Professional at $590 per workspace per year, and Team at $1,590 per workspace per year; Dify Enterprise is a separate private-deployment edition.

**Strengths:** The retrieval pipeline is a comprehensive one for a self-hostable package and saves weeks of integration work for document-heavy apps. Workspace members with editor rights can [edit the same workflow at the same time](https://docs.dify.ai/en/self-host/use-dify/build/workflow-collaboration).

**Limitations:** Dify's [license](https://github.com/langgenius/dify/blob/main/LICENSE) is "a modified version of the Apache License 2.0" that bars operating a multi-tenant environment without written authorization and requires a commercial license to remove or modify the logo or copyright in its frontend, so it is not OSI-approved as modified. Agent lifecycle management is thinner than in a workspace built for it, and complex custom logic belongs in code. Sim's Apache 2.0 core has no multi-tenant or branding conditions; Dify is the better pick when RAG apps are the job and its terms fit.

**Sources:** [Dify license](https://github.com/langgenius/dify/blob/main/LICENSE), [Dify pricing](https://dify.ai/pricing), [Docker Compose docs](https://docs.dify.ai/en/self-host/deploy/quick-start/docker-compose), [Sim vs Dify](/library/sim-vs-dify-open-source-ai-workspace-vs-llm-app-rag-platform).

### 6. n8n (source available)

[n8n](https://github.com/n8n-io/n8n) is a workflow automation product that has added AI agent nodes. Its [AI docs](https://docs.n8n.io/build/integrate-ai) describe workflows that "connect different LLM providers such as OpenAI, Anthropic, and Google, add tools and memory, and combine several models in one workflow." With about 208,000 GitHub stars it has the largest repository in this guide.

**Best for:** Teams migrating existing automation workflows toward AI without replatforming, especially when broad service connectivity matters more than deep agent reasoning.

**Pricing:** Self-hosted n8n [runs as the free Community edition without a license key](https://docs.n8n.io/deploy/host-n8n); Business or Enterprise license keys enable those editions. [n8n's pricing page](https://n8n.io/pricing/) lists cloud Starter at €20 per month and Pro at €50 per month, a self-hosted-only Business plan at €667 per month, all billed annually, and custom Enterprise pricing for cloud or self-hosted.

**Strengths:** A mature drag-and-drop editor, proven self-hosting, and a very large connector catalog. n8n's homepage advertises "500+ native integrations," while its [integrations directory](https://n8n.io/integrations/) says "Browse 2,000+ integrations." The two official pages give different counts.

**Limitations:** n8n uses the [Sustainable Use License](https://github.com/n8n-io/n8n/blob/master/LICENSE.md), which is source available and not OSI-approved, and files marked `.ee` require a separate n8n Enterprise License. Its AI features sit on top of an automation engine rather than being the core architecture. Sim fits when agents are the main job and an OSI-approved core matters; n8n is the better pick when you are extending automations that already run there.

**Sources:** [n8n license](https://github.com/n8n-io/n8n/blob/master/LICENSE.md), [n8n pricing](https://n8n.io/pricing/), [hosting docs](https://docs.n8n.io/deploy/host-n8n), [Sim vs n8n](https://www.sim.ai/comparisons/n8n), [Apache 2.0 vs fair-code](/library/apache-2-0-vs-fair-code).

### 7. OpenHands (coding agents)

[OpenHands](https://github.com/OpenHands/OpenHands) is a coding-agent project, not a general agent builder. Its current release, Agent Canvas, is "the self-hosted developer control center for coding agents and automations." It runs locally by default, can use agent backends in Docker, on VMs, or in company infrastructure, and runs the OpenHands agent or third-party agents such as Claude Code, Codex, and Gemini CLI.

**Best for:** Software teams that want self-hosted coding agents and engineering automations such as breaking GitHub issues into tasks and posting reports to Slack.

**Pricing:** The repository is MIT-licensed and free to self-host; OpenHands Cloud and OpenHands Enterprise are optional hosted backends.

**Strengths:** About 91,000 GitHub stars, very frequent releases, any-LLM support, and automations that run on a schedule or on webhook events from tools such as GitHub and Linear.

**Limitations:** The project labels its status as beta, and it is built for software delivery rather than business agents that work across CRMs, documents, and support tools. For those, use one of the platforms above; [AI coding agents vs AI workflow agents](/library/ai-coding-agents-vs-ai-workflow-agents) explains the split, and the [agentic AI coding tools comparison](/library/agentic-ai-coding-tools-what-they-are-and-how-the-top-options-compare) covers proprietary options such as Cursor and Claude Code. Sim fits when agents need to act across business systems with 270+ integrations, while OpenHands is the better pick when the agent's job is writing and shipping code.

**Sources:** [OpenHands MIT license](https://github.com/OpenHands/OpenHands/blob/main/LICENSE), [OpenHands README](https://github.com/OpenHands/OpenHands).

## How should you choose an open source AI agent platform?

Choose by team composition and use case first, then compare within that category. Comparing a Python framework against a visual workspace on one checklist is how teams end up six months into a tool that does not fit.

- **Choose LangGraph** if engineers need fine-grained state management, explicit branching, and human approvals in code.
- **Choose CrewAI** if work splits naturally into role-based tasks and Flows give you enough event-driven control.
- **Choose Microsoft Agent Framework** if you are migrating from AutoGen or Semantic Kernel or already build on Microsoft's stack; **choose [AG2 Classic](https://github.com/ag2ai/ag2-classic)** if you have AutoGen-style GroupChat code to keep running.
- **Choose Dify** if retrieval over documents is the primary job and its multi-tenant and branding conditions do not affect you.
- **Choose n8n** if you already run automations there and want to add AI steps without rebuilding.
- **Choose OpenHands** if the job is software delivery: coding agents working on repositories, issues, and CI.
- **Choose Sim** if a mixed team needs real-time collaboration, many model providers, human review, and deployment as an API, chat, or MCP tools in one workspace with an Apache 2.0 core.

**Self-hosting is a second decision.** It gives your team more control over infrastructure and data while making it responsible for availability, backups, security patches, secrets, model endpoints, observability, upgrades, and capacity. Ask three questions separately: can the software run on your infrastructure, does the license permit your intended production or commercial use, and can your team operate it reliably over time.

**Local models need the same care.** Self-hosted Sim connects to Ollama through `OLLAMA_URL` and to vLLM, LM Studio, or LiteLLM through compatible base URLs, without Sim Enterprise; CrewAI also documents Ollama. Before relying on local inference, assess streaming, tool calls, structured output, context limits, and the compute it needs. On Sim Cloud, workspace bring-your-own-key (BYOK) is available on every plan, and organization-level keys need Pro for Teams, Max for Teams, or Enterprise, per [Sim's cost guide](https://docs.sim.ai/platform/costs#bring-your-own-key-byok).
