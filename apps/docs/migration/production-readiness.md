Audit of [PR #9459](https://github.com/simstudioai/sim/pull/9459), October 30, 2026. The approved visual direction is preserved. This report distinguishes source, production-build lab, live-service and post-deployment evidence.

The implementation passes the verified pre-release checks, but production release is **not yet cleared**: successful real-provider/relevance testing and real-CDN verification remain outstanding. The largest mobile reference also misses the stated performance target. Detailed statuses and operational prerequisites follow.

The platform `@Docs` path embeds search hits; a full read is a separate VFS operation. Existing platform fetch retries/timeouts and unavailable-versus-no-results behavior remain intact. Public lexical queries cover representative workflow/integration topics, but deterministic vectors do not establish semantic ranking quality. Unchanged platform limitations remain: read/grep trusts an HTTP 200 body without a docs-specific content-type/byte guard; similarity and manifest-liveness filters run after the SQL candidate limit, which can reduce the returned count; scope and corpus exclusions run before the limit; the tool does not propagate its caller abort signal. The real-consumer fixture proves the current successful flow, not immunity to every upstream failure. Chunking changed from the old publisher's 1,024-token chunks with 200-token overlap/minimum 100 characters to heading-based chunks capped at 6,000 characters without overlap. The corrected chunker preserves fitting paragraphs, complete code lines and fences, table headers and continuation context. Excerpts are explicitly labeled; a code excerpt is not necessarily a standalone JSON value or executable program. Oversized unbreakable text/code fails compilation with page/heading context. Repeated generic Input/Output headings and the changed chunk strategy still require the fixed-query live relevance review; schema compatibility is not ranking parity.

Publication prepares all new vectors for a page before its transaction; a failed replacement retains that page's old rows. Earlier successfully updated pages may remain updated after a later failure: publication is not a whole-catalog snapshot. Retired rows are deleted only after every current page succeeds. The public docs search excludes stale catalog chunks, but the platform direct-table reader does not validate catalog hash, model, heading or citation-origin freshness and can return older chunks during a partial publication. Scoped repair does not retire other pages. URL-only repairs retain vectors. Workflow serialization and a session advisory lock exclude cooperating publisher/check invocations; arbitrary SQL and the removed legacy publisher do not participate in that lock. Provider retries are limited to three attempts within 30 seconds per batch for 429/5xx; authentication and malformed vectors are not retried.

A single authorized real-provider attempt against an isolated database returned HTTP 401. No production index was accessed or mutated. The optional live harness now accepts one to three publisher attempts and counts attempted inputs correctly after a transient retry; the existing real-HTTP retry suite proves counter semantics, while the live flow still requires credentials. Successful live embeddings and fixed-query semantic relevance remain release requirements; default fixture success is not a substitute.

## HTTP, SEO and machine access

The HTTP suites cover complete HTML/Markdown/JSON representations, aliases, all corpus routes/assets/anchors, API schemas/examples, llms discovery, pagination, invalid paths and inputs, real 404s, redirect behavior, native header merging, and the supported MCP client's discovery/read/search/error paths. The aggregate llms corpus deliberately excludes generated operation bodies; each operation remains listed and individually retrievable.

Current canonicals, social metadata, JSON-LD and sitemap target `https://docs.sim.ai`. Canonical articles populate the sitemap. The utility gallery at `/design-system` is `noindex,nofollow` and excluded from it; public search/discovery and llms interfaces remain crawlable without an `X-Robots-Tag` exclusion. These interfaces are not additional canonical article URLs. Dates come from Git, not build time. Core reading content is server-rendered; the no-JS browser checks exercise visible panels rather than merely searching HTML strings. Client-navigation checks verify updated unique metadata without a document reload.

Local production negotiation covers explicit and mixed Accept quality values, wildcards, q=0, HTML/Markdown ordering and RSC `Vary` preservation. Five additional maintained checks verify HTML/Markdown HEAD representation headers, matching HTML ETag GET/HEAD returning 304 with Vary retained, and an HTML ETag not suppressing Markdown. These checks do not establish wire-level bodylessness. The local 179 production build passed all 12; final-head CI evidence is recorded below. Markdown does not emit its own ETag, so Markdown 304 behavior is not claimed. Prior production responses omitted `Accept` from `Vary`; local fixed behavior does not prove new deployed CDN behavior. The PR preview remains Vercel-authenticated and non-indexable. Protection was not removed. Public production later returned HTTP 403 during Lighthouse measurements; automated requests stopped, and remaining samples are unverified.

Google's [AI features guidance](https://developers.google.com/search/docs/appearance/ai-features) supports ordinary crawlability, useful visible text and accurate structured data. No AI-only hidden copy, speculative schema or ranking claims were added. Llms files are retrieval interfaces, not evidence of indexing or AI visibility.

## Measurement method

Production builds only; builds and repeated suites run in CI. One browser case at a time, seven representative routes, three repetitions. Chromium/Playwright 1.61.1 and Lighthouse 13.6.0 are pinned. The final CI uses Node 24.22.1, Bun 1.4.4 and Chromium 149. Installed Next.js is 16.4.1; the installed Image/Link/App Router documentation and implementation were consulted instead of assuming behavior from another version. Early benchmark reports mislabeled Bun's Node-compatibility `process.version` as the Node executable version; the final harness records `node --version` and the Bun compatibility value separately. Desktop: 1440×1000/DPR1, unthrottled. Navigation mobile: 390×844/DPR3, 150 ms latency, 1.6 Mbps download, 750 Kbps upload, CPU ×4. Lighthouse mobile uses its saved default simulated profile, which is distinct from those navigation conditions.

Cold means a fresh browser context, not a new server process; server-module and optimizer caches persist between trials. A separate bounded optimizer check distinguishes a new variant MISS from a repeated HIT. Navigation ends after the destination H1 and nonempty article are visible and two frames have painted. Useful image decoding is timed separately. Uncached navigation disables browser HTTP cache and aborts prefetch; intent navigation allows normal caching and a 500 ms hover/focus dwell. Warm reloads, history/scroll, consecutive cross-section/heavy-page moves, search, API controls/copy, themes and media/workflow expansion are recorded separately. UI timing includes automation overhead. Early shortcuts before hydration are explicitly separated from controls with demonstrated readiness. The final `66faa48` run handled all three early desktop shortcuts and none of the three throttled-mobile shortcuts; a page-level shortcut is not available before its JavaScript listener loads. Navigation has a reliable meaningful-content-paint boundary; a separate first-pixel feedback boundary was not captured for every route, so no such result is claimed.

Report median, range and raw n=3 observations, not p95. A 100 ms local-control target and 200 ms warm desktop-navigation target are engineering budgets, not universal guarantees. Actual request/transfer sizes, response headers, long tasks, DOM metrics and image sources accompany the raw measurements. The compact CSV sums only known nonnegative encoded body sizes; missing sizes and negative Playwright cache values are not invented wire bytes. HTML references are not mistaken for executed JavaScript, and distinct RSC segment requests are not labeled duplicates solely because they share a pathname.
