Manage knowledge bases, indexed documents, search, tags, and connector syncs.

`sim knowledge` is also spelled `sim kb`.

These commands accept the [global options](/cli/commands#global-options).

## Knowledge bases

### List knowledge bases

```bash
sim knowledge list [options]
```

**Options**

<CommandTable>

| Option | Required | Description |
| --- | --- | --- |
| `--scope <value>` | No | Lifecycle scope: active or archived knowledge bases. Use Restore knowledge base to recover archived entries. Folder paths resolve only active folders, so filtering by an archived folder returns no matches. Defaults to "active". Accepted values: `active`, `archived`. |
| `--folder <value>` | No | Folder path as shown in the app; the leading / is optional. |
| `--search <value>` | No | Case-insensitive substring match against the resource name. |
| `--sort-by <value>` | No | Field used to sort the result. Do not rely on case-insensitive ordering when sorting by `name`. Defaults to "createdAt". Accepted values: `name`, `createdAt`, `updatedAt`. |
| `--sort-order <value>` | No | Sort direction. Defaults to "asc". Accepted values: `asc`, `desc`. |
| `--limit <n>` | No | Maximum items to return (0 for everything). Defaults to `0`. |

</CommandTable>

API request and response schemas: [listKnowledgeBases](/api-reference/knowledge-bases/listKnowledgeBases).

## Search

### Search knowledge

```bash
sim knowledge search [options]
```

**Options**

<CommandTable>

| Option | Required | Description |
| --- | --- | --- |
| `--kb <value...>` | Yes | Knowledge base ID (repeatable) (space-separated, or @path / @- with one value per line; @@value for a literal leading @). |
| `--query <value>` | No | Text to search for. |
| `--top-k <value>` | No | Maximum number of search results to return. Must be a whole number between 1 and 100. Defaults to 10. |
| `--tag-filters <json\|@file>` | No | Tag filters as [&#123;"tagName":"...","operator":"...","value":"..."&#125;] (JSON, or @path / @- to read a file or stdin). |
| `--search-mode <value>` | No | Search algorithm. Accepted values: `vector`, `hybrid`. |
| `--reranker-enabled` | No | Reorder retrieved chunks with a reranking model before truncating to `topK`. Ignored for tag-only searches. A completed reranking call adds a search unit. If reranking is unavailable, results keep their retrieval order; check `rerankerStatus`. |
| `--no-reranker-enabled` | No | Send --reranker-enabled as false. |
| `--reranker-model <value>` | No | Reranking model to use when `rerankerEnabled` is true. Defaults to `rerank-v4.0-fast`. Accepted values: `rerank-v4.0-pro`, `rerank-v4.0-fast`, `rerank-v3.5`. |
| `--reranker-input-count <value>` | No | How many candidate chunks to retrieve before reranking. Defaults to four times `topK`, capped at 100. A larger pool costs more retrieval work but gives the reranker more to choose from. |

</CommandTable>

API request and response schemas: [searchKnowledge](/api-reference/knowledge-bases/searchKnowledge).
