An AWS credential holds one AWS identity for the whole workspace. Every AWS block (S3, DynamoDB, Lambda, SQS, Athena, CloudWatch, and the rest) can select it instead of taking access keys typed into the block.

<Callout type="info">
Blocks that already use access keys keep working exactly as they are. Selecting a saved credential is optional; clear it and the block goes back to its own keys.
</Callout>

## Choose how Sim signs in

| Option | What Sim stores | When to use it |
| --- | --- | --- |
| **IAM role (keyless, via Sim OIDC)** | Nothing secret: only the role ARN | Recommended. No long-lived keys to rotate or leak. |
| **Access keys that assume an IAM role** | An access key pair, used only to assume the role | Your AWS account doesn't allow OIDC providers, or you need an external ID. |
| **Access keys** | An access key pair | The same behavior as keys typed into a block, shared across blocks. |

Every option resolves on Sim's servers at run time. Keys and session tokens never appear in block outputs, logs, or anything a model sees. Each assumed-role session is named `sim-<execution ID>`, so runs are traceable in CloudTrail.

## Set up a keyless IAM role [#keyless-role]

<Steps>
  <Step>
    In Sim, open **Integrations**, add an **AWS credential**, and choose **IAM role (keyless, via Sim OIDC)**. Keep the dialog open; it shows the values for the next steps.
  </Step>
  <Step>
    In the AWS IAM console, open **Identity providers → Add provider**, choose **OpenID Connect**, and enter the **Identity provider URL** and **Audience** from the dialog. You only do this once per AWS account.
  </Step>
  <Step>
    Create a role (or edit an existing one) and set its trust policy to the **Role trust policy** shown in the dialog. It trusts only this credential's **Subject**, so no other Sim credential, workspace, or customer can assume the role.
  </Step>
  <Step>
    Attach the permissions your workflows need to the role, then paste its ARN into the dialog and save. Sim verifies the connection by assuming the role before saving it.
  </Step>
</Steps>

<Callout type="warn">
The subject is unique to the credential. Reconnecting a keyless credential with a new subject means updating the role's trust policy to match.
</Callout>

## Use access keys

Create an IAM user (or use an existing one) with an access key, choose **Access keys** or **Access keys that assume an IAM role**, and enter the key pair. For an assumed role, add the role ARN and, if the role's trust policy requires one, the external ID. Sim checks the keys with `sts:GetCallerIdentity` before saving.

## Self-hosted deployments

Keyless roles need two things on a self-hosted deployment:

- `WORKLOAD_IDENTITY_SIGNING_KEY`: a PKCS#8 PEM RSA private key that signs Sim's tokens.
- An issuer AWS can reach over the public internet. It defaults to `<NEXT_PUBLIC_APP_URL>/oidc/workload`; set `WORKLOAD_IDENTITY_ISSUER` to pin it. Trust policies reference this URL, so never change it once roles trust it.

To rotate the signing key, move the old key to `WORKLOAD_IDENTITY_PREVIOUS_KEY` and set a new `WORKLOAD_IDENTITY_SIGNING_KEY`. Both keys stay published until you remove the old one.

Without a signing key, the keyless option is unavailable and access keys work as usual.
