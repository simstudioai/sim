[Oracle Financial Consolidation and Close](https://www.oracle.com/performance-management/financial-consolidation-close/) (FCCS) is a Cloud EPM business process. This integration provides 40 actions for metadata discovery, consolidation/translation, data and journal transfers, intercompany matching reports, job monitoring, and external repository files.

### Connection and permissions

Create an **Oracle EPM service account** credential with the REST base URL, username, and password. The URL is the HTTPS environment origin, optionally including a gateway prefix—not a URL ending in `/HyperionPlanning/rest/v3`, `/interop/rest`, or an API resource. Select that credential in the block. Sim injects authentication and the destination on the server; workflows cannot override them through tool arguments. Use the username format required by your Oracle identity domain.

Grant only the Oracle application, member, rule, journal, and migration permissions needed by the selected actions. Rules require Service Administrator or a Power User with Rule Launch access. Journal actions require the appropriate consolidation-journal security role and read/write member access; opening/closing periods requires Service Administrator or Consolidation Journals – Manage Periods. Repository transfers require Service Administrator or an application role with Migrations – Administer. Other operations have their own role requirements; do not assume that successful connection grants write permission. See [rules](https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/prest/rules.html), [journal actions](https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/prest/fccs_perform_journal_actions.html), [journal periods](https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/prest/fccs_perform_journal_update.html), and [file upload](https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/prest/upload.html).

### Selectors and manual inputs

Use the block's credential selector to connect and select the Oracle EPM service account. As with NetSuite, the current shared catalog does not expose service-account-only connections through the integration-detail page or Copilot/VFS credential discovery. The block connection and execution path remains available.

Choose an FCCS application, then its cube and dimensions. Member, entity, period, and scenario pickers retrieve the relevant hierarchy on the server. Each has an Advanced/manual alternative. Enter literal Oracle names and repository paths without URL encoding; Sim preserves them and the foundation encodes them once. Oracle's [dimension/member naming restrictions](https://docs.oracle.com/en/cloud/saas/financial-consolidation-cloud/agfcc/restricted_dimension_names.html) still apply.

Hierarchy retrieval is capped at 2 MiB, 10,000 nodes, and 64 levels. Other JSON responses are capped at 8 MiB. A picker fails explicitly if it cannot provide a complete result within its budget; it never implies a truncated list is complete. Dimension pickers allow up to 1,000 dimensions; configured-job and file pickers allow up to 10,000 records. Use manual values for larger tenants. Manual file download/delete can find an external file beyond 10,000 entries, but still require a repository inventory within the 8 MiB response limit to exclude LCM snapshots. Rules and rulesets are deployed job definitions. Saved profiles, intercompany report definitions, and configurable-consolidation ruleset names remain manual where Oracle does not document a listing API.

### Jobs and files

Submission actions return promptly. Wire the returned `jobId` into **Wait for Job** or **Get Job**; Oracle's numeric `jobId` and `jobID` spellings normalize to one string. Status `-1` is in progress, `2` is cancel pending, `0` is success, and other codes are terminal failures. Wait is cancellable and bounded by both the requested duration and the workflow deadline. Job IDs can also be entered manually; there is no invented job-instance listing endpoint. Job Details supports only data/metadata import/export; Child Job Details supports only metadata import/export. Pagination tools return one page, not an accumulated full history. See [job status](https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/prest/retrieve_job_status.html) and [job details](https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/prest/retrieve_job_status_details.html).

Use **Upload File** before file-based imports. Input must be an authorized Sim UserFile, not an arbitrary URL. Buffered uploads and stored download outputs have a **100 MiB (104,857,600 bytes)** cap, checked against known size and actual bytes. Downloads become execution-scoped UserFile references, not inline/base64 content. Overflow stops transfer and cleans up partial storage; files are never truncated. An Oracle export can succeed even when Sim cannot materialize its oversized output. Retrieve that file outside Sim or use a narrower export definition.

Repository operations exclude LCM snapshots. Upload takes a basename plus an optional inbox/outbox directory and does not overwrite an existing file. Download/delete take an exact repository path. A JSON response from Oracle's download API is an error, not a binary file. See [download](https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/prest/download.html).

### Contract limitations and workflow boundaries

Numeric data slices accept numbers, decimal/percentage strings (such as `"70%"`), and `"#missing"`; numeric strings are capped at 1,024 characters. They do not enable Planning Text, Date, Smart List, or supporting-detail workflows. See [Import Data Slices](https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/prest/import_dataslices.html).

- Saved data, metadata, exchange-rate, journal, and report definitions must already exist in Oracle. Their names, runtime prompts, and required overrides depend on the tenant. This is input configuration, not an undocumented response schema. Preserve parameter casing and use the documented parameters for the selected job family.
- Consolidation/translation wrappers use the seeded `Consolidate`, `ForceConsolidate`, `Translate`, and `ForceTranslate` rules with `Entity`, `Period`, `Scenario`, and `Year`. Other deployed rules remain available through Run Rule. See Oracle's [automation rules table](https://docs.oracle.com/en/cloud/saas/financial-consolidation-cloud/agfcc/appendix_integrations_automated_integ_table.html).
- Application/member outputs project stable documented fields, without guessed application-type enums or tenant metadata. Journal Detail is deferred because Oracle's documented line-item structure is incomplete; Application Summary is excluded because its format is unstable.
- Oracle's journal request tables show a `parameters` object, while nearby sample inputs are flat. This integration follows the formal parameter tables. Journal Period Update accepts either the documented status/detail result or the documented scenario/year/period/action echo and verifies the requested period. Tenant verification of these inconsistent examples remains advisable.
- Configurable-consolidation import/export return only the documented text submission acknowledgment—no job ID or completion result is fabricated. Inspect Oracle's Job Console for completion and artifact information. See [ruleset export](https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/prest/fccs_export_consol_rules.html) and [ruleset import](https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/prest/fccs_import_consol_rules.html).
- Intercompany support runs an existing matching report; it does not invent a reconciliation or approval API. The integration excludes Fusion Financials, Planning-specific workflows, Data Integration pipelines/mappings, Enterprise Journals, Supplemental Data Manager, Task Manager, environment administration, and triggers.

## Usage Instructions

Connect Financial Consolidation and Close using an Oracle EPM service account. Discover applications and metadata, run consolidation and translation rules, transfer data and journals, generate intercompany matching reports, and retrieve bounded repository files. Uses Cloud EPM APIs; excludes Fusion Financials, Data Integration, Planning workflows, environment administration, and LCM snapshots.
