[Oracle EPM Data Integration](https://www.oracle.com/erp/performance-management/) connects source data to configured EPM targets. This block operates existing Data Integration/Data Management configurations: connections, integration and pipeline submissions, data rules, batches, reports, mappings, snapshots, POV locks, and supporting repository files. It does not implement direct Planning, FCCS, Tax, or Profitability APIs, or create pipelines and their constituent product jobs.

## Connect an account

Use the existing **Oracle EPM Cloud** reusable service-account credential. Enter the environment's HTTPS **REST Base URL**, integration username, and password. Omit `/epmcloud` and API endpoint paths; include a gateway prefix only when required by your deployment. The credential's destination is authoritative, and credentials remain server-side. This uses Oracle's documented [Basic authentication](https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/prest/authentication.html); it is not a new OAuth login flow.

Use a dedicated integration user with the roles required by the selected endpoint and access to the configured application. Check the tenant's enabled features and permissions before writes. Oracle's [POV page](https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/prest/fdmee_lock_unlock.html) contains inconsistent role descriptions between its prerequisite prose and role table; verify the required role with your administrator instead of assuming that the least-privileged role can perform every action.

## Submission and completion are different

**Run Integration** and **Run Pipeline** expose only `httpStatus` and `data` (uninterpreted Oracle JSON). Their official [integration](https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/prest/fdmee_integration_jobtype_106x0fea7396.html) and [pipeline](https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/prest/fdmee_run_pipeline.html) pages establish requests but not the response contract needed to extract a reliable execution ID. A successful Sim return means the HTTP/JSON response was retrieved, not that Oracle accepted or completed the job. These two tools have no automatic waiting, invented job fields, or submission retry. Inspect the response and Oracle UI; do not build a workflow around an assumed nested execution-ID field.

Other documented job tools return immediately unless **Wait for Completion** is enabled. Waiting lasts at most five minutes, subject to the workflow deadline and cancellation, with a two-second initial delay between polls and a ten-second maximum delay. The first status read is immediate. Oracle status `-1` and cancel-pending `2` remain pending; `0` succeeds; `1`, `3`, and `4` are unsuccessful terminal states. Unknown states fail explicitly. Numeric status takes precedence over contradictory status text in examples. See [job status](https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/prest/fdmee_jobstatus_di.html).

Keep `httpStatus`, Oracle `status`, and Sim's framework status separate. HTTP 200 alone does not prove completion. If waiting stops, the failure output retains the known `jobId` and latest available status; use **Get Job Status** to resume observation, not the submission action. Cancellation or a local timeout does not cancel a remotely accepted Oracle job. A timed-out submission may already have changed Oracle state; inspect Oracle before retrying manually.

## Inputs and tenant-defined behavior

- Integration periods use Oracle expressions such as `{Jan-26}` or `{Jan-26}{Mar-26}`. Quick Mode requires its documented execution mode. Import/export modes depend on the configured source/target and load mode. Source filters and target options use tenant-defined English display names; native file integrations do not support source filters. Follow the [integration request documentation](https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/prest/fdmee_integration_jobtype_106x0fea7396.html) and your tenant configuration.
- Pipeline names are the pipeline **code**: 3–30 alphanumeric characters. Use **Get Pipeline Details** to inspect documented variables, stages, and jobs, then submit variables by their actual names. Do not assume every pipeline defines the same variables. See [pipeline details](https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/prest/get_pipeline.html).
- **Update Connection** updates the documented source-system option array. Secret options that require encryption must contain values generated by Oracle's encryption workflow (the encrypted password-file contents), not plaintext or Sim's credential password. This integration does not encrypt these values. See [connection APIs](https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/prest/di_connections_update_a_connection.html).
- Data rules require explicit start/end periods and import/export modes; report parameter names depend on the selected report. See [data rules](https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/prest/fdmee_run_data_rule.html), [batches](https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/prest/fdmee_run_batch.html), and [reports](https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/prest/fdmee_execute_report.html).

## Selectors and limits

Connections and repository files have documented list-backed selectors. Location suggestions are scoped to **Application**, **Period**, and **Category** and come from POV rows. Application-summary rows (whose location equals the application name) are excluded. These suggestions are not a complete location catalog; a real location with the same name is also ambiguous, so enter it manually.

Switch selector fields to Advanced mode for manual names or references. Integrations, data rules, pipelines, periods, and jobs use manual names/codes/IDs because the available documentation does not establish trustworthy list item schemas for those catalogs. A documented collection URL alone is not a response contract.

JSON requests/responses are bounded to 16 MiB. Documented collections and pipeline arrays are bounded to 10,000 entries, and tenant option/variable maps to 100 entries. Exceeding a limit fails explicitly rather than silently truncating or accumulating more pages. Selectors may also apply the shared platform's display limits; manual inputs remain available.

## Repository files and destructive workflows

- **Upload File** accepts exactly one authorized Sim UserFile, through the basic upload field or an advanced resolved file reference. Both upload and download are capped at **100 MiB**, including actual streamed bytes, regardless of higher Oracle limits. Upload uses the direct binary API, with no chunked/multipart Oracle protocol or overwrite option. Set **Upload Directory** to `inbox` (or a supported subfolder) for Data Integration input files; omitting it uses the repository root. Upload status `-1` means extraction is still running, not completed. See [upload](https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/prest/upload.html).
- Pass raw complete repository filenames, including folders, not pre-encoded URLs. Download encodes the whole filename as one path parameter, supports Oracle's slash/backslash forms, and rejects traversal. JSON responses from this endpoint are errors, not downloaded files. Binary results stream into authorized workflow execution storage and return a canonical UserFile. Download requires valid workflow, workspace, and execution context. See [download](https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/prest/download.html).
- Mapping imports read uploaded `inbox` CSV/TXT/XLS/XLSX files. **REPLACE** replaces existing mappings; **MERGE** is Oracle's default when omitted. Mapping exports require a location and dimension (or `ALL`) and produce an `outbox` file. The export format is selected by filename extension, not an invented export-mode parameter. Oracle's export page disagrees on XLS versus XLSX; use a documented compatible format such as CSV or confirm your tenant's spreadsheet behavior. See [mapping import](https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/prest/fdmee_import_data_mapping.html) and [export](https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/prest/fdmee_export_data_mapping.html).
- **Import Data Integration** clears existing target Data Integration setup/staging data before restoring the snapshot; it does not merge. Oracle documents a placeholder `jobId: 0`, which cannot be polled by **Get Job Status**, so this action never auto-waits. Verify completion in Oracle. **Export Data Integration** supports ALL, ALL_INCREMENTAL, INCREMENTAL, and SETUP with the documented `overwriteFile` option; Oracle produces the snapshot in outbox. See [snapshot import](https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/prest/fdmee_import_data_snapshot.html) and [export](https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/prest/fdmee_export_data_snapshot.html).
- **Set POV Lock** changes the selected application or location scope. **Delete File** permanently removes the specified repository file or snapshot. Review scope and replacement options before running these actions. See [POV locks](https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/prest/fdmee_lock_unlock.html) and [file deletion](https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/prest/delete_files_v2.html).

Typical workflows: upload an inbox file and run an existing data rule; export mappings and download the completed output; run a report and download its output file; or export a SETUP snapshot before an explicitly approved restore. For documented jobs, check successful completion before using output filenames. No live tenant execution is required to configure the block, and no tenant-specific response fixtures are bundled.

## Usage Instructions

Use existing Oracle EPM Data Integration and Data Management configurations with 20 actions. Integration and pipeline submissions return opaque Oracle JSON without assumed completion or execution-ID fields. Other documented jobs support optional bounded waiting. File transfers are capped at 100 MiB. Snapshot import clears target data; connection updates, replacement modes, POV locks, and file deletion change provider state. Product-specific Planning, FCCS, Tax, and Profitability APIs are outside this block.
