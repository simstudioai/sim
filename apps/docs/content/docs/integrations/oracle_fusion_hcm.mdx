The Oracle Fusion Cloud HCM integration provides **76 tools: 67 reads and nine administrative writes**. It uses the shared Oracle Fusion foundation, versioned `11.13.18.05` HCM REST resources, and REST Framework version 9. The original 18 workforce/absence tools and four selectors retain their contracts; payroll, compensation, talent, and Time and Labor add 58 tools and 12 selectors in this same block.

## Connection and access

Select a reusable Oracle Fusion integration-user credential. The stored application origin is authoritative; callers cannot replace the tenant, authentication headers, or REST resource family. Assign only the function/data privileges and security profiles needed for each workflow. A workforce reader is not automatically a payroll, compensation, talent, or time administrator.

Oracle must provision the relevant modules and REST capabilities. Payroll access depends on the legislative data group, country legislation, payroll setup, employment level, and secured person population. Compensation depends on salary bases, element setup, and assignment eligibility. Talent sections and performance documents are secured separately; some capabilities depend on enabled profile content and feature availability. Time intake requires Time and Labor configuration, valid time attributes, reporter/assignment eligibility, and applicable entry/audit rules. These tools do not bypass tenant permissions or lifecycle validations, and do not imply that every resource is available in every edition, country, or tenant release. Confirm the exact privileges with the tenant security administrator before enabling writes.

Oracle references: [API index](https://docs.oracle.com/en/cloud/saas/human-resources/farws/index.html), [authorization](https://docs.oracle.com/en/cloud/saas/human-resources/farws/Authorize.html), [collection queries](https://docs.oracle.com/en/cloud/saas/human-resources/farws/Query_a_Collection.html), and [pagination](https://docs.oracle.com/en/cloud/saas/human-resources/farws/Navigate_a_Collection.html).

Absence date filtering still requires an absence type and a complete date pair.

## Payroll records and compensation

Payroll assignment `payrollAssignmentId` is Oracle's `RelationshipGroupId`, **not** the HR `AssignmentId`. Opaque/date-effective resource keys are resolved under their actual parent using validated self-links. Supply identifiers as positive decimal strings; server-side serialization preserves integer request fields exactly, including nested element input IDs.

Assigned-payroll creation requires payroll identity and both effective and assignment date ranges. Its update tool supports only the documented record fields, not payroll transfers. Effective-dated updates require an explicit `CORRECTION` or `UPDATE` mode and effective date. Correction can change historical data; update begins an effective-dated change. Element input values remain text or explicit null, so decimal strings are not rounded.

Salary creation and correction support **user-entered salary bases only**. Creation requires HR assignment, salary basis, amount, and effective date range; it uses `MultipleComponents=N`. Correction changes the amount on the selected historical salary record rather than creating a new salary interval. Neither tool submits an approval request. Standard, simple, and rate component reads are separate choices within List Salary Components; only the selected family is populated and paginated.

Payroll run-result values, balance slots, and goal completion percentages remain their documented strings. Balance `value1`–`value10`, definition IDs, and context/dimension labels are preserved without inventing net-pay or year-to-date meanings.

Operation contracts: [assigned payroll creation](https://docs.oracle.com/en/cloud/saas/human-resources/farws/op-payrollrelationships-payrollrelationshipsuniqid-child-payrollassignments-payrollassignmentsuniqid-child-assignedpayrolls-post.html), [element entry creation](https://docs.oracle.com/en/cloud/saas/human-resources/farws/op-elemententries-post.html), [salary creation](https://docs.oracle.com/en/cloud/saas/human-resources/farws/op-salaries-post.html), [salary correction](https://docs.oracle.com/en/cloud/saas/human-resources/farws/op-salaries-salaryid-patch.html), and [salary bases](https://docs.oracle.com/en/cloud/saas/human-resources/farws/op-salarybasislov-get.html). Required fields follow the formal operation schemas even where abbreviated examples omit them.

## Time and Labor

Time-record reads select the `TimeCardEntry` layer; time-card reads select `ProcessedTimecard`. Provide a person number and ordered ISO 8601 timestamps with explicit offsets. Configuration discovery uses the documented `ORA_HWM_TIME_RECORDS_REST` context. Discover attribute field/usage IDs, data-source usage IDs, and criteria binds before requesting values. The payroll-time-type selector binds `pAssignmentId` and `pEffectiveDate`; tenants with different attribute bindings can use the typed value-list tool.

Create, update, and delete time-entry tools all **POST intake requests** to `timeRecordEventRequests`, with fixed `ADD`, `UPDATE`, or `DELETE` operations. They never directly PATCH or DELETE `timeRecords`. Reporter IDs are person numbers, including leading zeros. Update/delete require the existing record ID and current version. Create accepts a complete start/stop range or a positive measure, including documented combinations of both. Update can change individual time or attribute fields, including only the stop time. Optional `referenceDate` controls processing for entries spanning multiple days; it is not a substitute for a quantity-entry date. Oracle validates entries against the worker's time configuration. Qualifiers are bounded typed name/value pairs from time configuration discovery.

Intake always uses asynchronous `processInline=N`. Choose `TIME_ENTER` (default), `TIME_SAVE`, or `TIME_SUBMIT` explicitly. A returned request ID is only a receipt—not completed processing, approval, or payroll transfer. Read request events for processing status, then event messages for validation identifiers/fields. Request headers do not contain a fabricated aggregate processing status, and message results do not invent undocumented message text. Nested POST children use Oracle's documented parent-create semantics: the service establishes generated request/event parent identifiers.

References: [time records](https://docs.oracle.com/en/cloud/saas/human-resources/farws/op-timerecords-get.html), [time attribute values](https://docs.oracle.com/en/cloud/saas/human-resources/farws/op-timeattributevalues-get.html), [time intake](https://docs.oracle.com/en/cloud/saas/human-resources/farws/op-timerecordeventrequests-post.html), and [processing events](https://docs.oracle.com/en/cloud/saas/human-resources/farws/op-timerecordeventrequests-timerecordeventrequestid-child-timerecordevent-get.html).

## Sensitive data and failures

Existing workforce projections are unchanged and are not enriched with compensation, payroll, or talent data. Those sensitive fields are confined to their dedicated tools. Selector options omit salary amounts and payroll results. Outputs omit raw self-links, flexfields, attachments, certificate numbers/URLs, private talent narratives, medical data, tax/payment administration, and unrelated child records. Location catalog locality fields remain available.

The foundation pins the credential-bound origin, validates public DNS, prohibits redirects, preserves large integer identifiers, caps responses at 5 MiB, and propagates cancellation. Authentication, authorization, missing-resource, rate-limit, malformed-response, and timeout failures retain safe status semantics without raw Oracle errors. GET retries remain bounded by the shared client. Mutations are never automatically replayed by this integration; ambiguous failures are non-retryable. Inspect Oracle state before a deliberate retry. No live-tenant writes are used for automated validation.

Before production use, verify module availability, least-privilege data access, date-effective behavior, salary-basis restrictions, configured time attributes/audit reasons, and asynchronous processing in an authorized non-production tenant. CI uses mocked documented contracts, not a tenant connection.

## Usage Instructions

Connect to Oracle Fusion Cloud HCM using a reusable integration-user credential. Preserve workforce and absence reads while accessing dedicated payroll, compensation, secured talent, and Time and Labor tools. Administrative salary and payroll-record writes require separate privileges. Time-entry intake is asynchronous: inspect events and messages before treating it as complete. No payroll orchestration, Recruiting, Learning, tax, or payment administration.
