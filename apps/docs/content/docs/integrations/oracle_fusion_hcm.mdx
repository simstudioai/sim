The Oracle Fusion Cloud HCM integration is strictly read-only. It builds on Sim's shared Oracle Fusion foundation and uses Oracle's versioned `11.13.18.05` REST resources with REST Framework version 9 to read public worker profiles, assignments, reporting relationships, absences, absence types, and workforce structures.

## Connection setup

1. Create or select a reusable Oracle Fusion integration-user credential. The credential stores the canonical Oracle Fusion application origin and dedicated integration username/password; workflows receive only its credential ID, never the raw values.
2. The stored application origin is authoritative. Vanity domains, paths, ports, non-HTTPS URLs, and caller-supplied replacement destinations are rejected.
3. Give the integration user only the data roles and security profiles required for the records the workflow must see. Relevant Oracle grants commonly include **Public Workers Read Only**, **Absences Read Only**, **Absence Types List of Values**, and **Workforce Structures Read Only**. Exact duty-role composition varies by tenant, and data security profiles determine which active or public workers are visible.

Oracle references: [REST API index](https://docs.oracle.com/en/cloud/saas/human-resources/farws/index.html), [Quick Start](https://docs.oracle.com/en/cloud/saas/human-resources/farws/Quick_Start.html), [authorization](https://docs.oracle.com/en/cloud/saas/human-resources/farws/Authorize.html), [collection queries](https://docs.oracle.com/en/cloud/saas/human-resources/farws/Query_a_Collection.html), and [pagination](https://docs.oracle.com/en/cloud/saas/human-resources/farws/Navigate_a_Collection.html).

## Available operations

| Area | Operations |
| --- | --- |
| Workers | List Workers; Get Worker |
| Assignments | List Worker Assignments; Get Worker Assignment |
| Reporting | List Worker Managers; List Worker Direct Reports |
| Absence management | List Absences; Get Absence; List Absence Types |
| Workforce structures | List Jobs; List Job Families; List Departments; List Locations; List Positions; List Business Units; List Legal Employers; List Grades; List Person Types |

List operations return one page. `limit` defaults to 20 and cannot exceed 100; `offset` defaults to 0. Use the returned `hasMore` and `nextOffset` values to request another page deliberately. Search is limited to 200 characters and is converted into resource-specific predicates; raw Oracle `q`, `finder`, `fields`, headers, ordering, and expansion parameters are not accepted.

Absence date filters require an absence type and a complete start/end pair. Get Absence uses Oracle's documented absence-entry finder and requires exactly one matching record.

Public workers and their assignments describe active records as of the current date, not a historical or termination feed. Oracle directs bulk extraction to HCM Extracts and change detection to Atom feeds; these tools are not intended for either use. See [Public Workers](https://docs.oracle.com/en/cloud/saas/human-resources/farws/api-public-workers.html).

Recruiting, payroll, time and labor, talent, writes, and triggers remain separate future scope.

## Data minimization and errors

The integration returns explicit field allowlists. It excludes photos, street addresses, phone numbers, comments, absence reasons, medical or maternity data, certifications, attachments, entitlements, payroll details, audit usernames, budgets, costs, and flexfields. Location catalog records may include non-personal locality fields such as country, city, region, and postal code.

Validation failures are reported before contacting Oracle. The shared Oracle transport pins the credential-bound origin, resolves and validates public DNS, prohibits redirects, preserves large integer identifiers losslessly, and caps every response at 5 MiB. Authentication and authorization failures preserve 401 and 403 semantics; missing resources return 404; exhausted rate limits return 429; malformed or oversized upstream responses return 502; and local request timeouts return 504. These HCM tools issue only GET requests. The shared client allows at most one retry (two attempts total), only for Oracle 429, 503, and 504 responses within its retry budget.

## Usage Instructions

Connect to Oracle Fusion Cloud HCM with a reusable, least-privilege integration-user credential. Read public worker profiles, assignments, reporting relationships, absences, absence types, and workforce structures without exposing write operations, raw credentials, or sensitive HR fields.
