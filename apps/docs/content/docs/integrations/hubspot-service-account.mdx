Connect HubSpot with a service key, or with the access token of an existing legacy private app. Both are scoped Bearer credentials for your HubSpot account: select the CRM scopes your workflows need when you create one.



## Legacy app availability

HubSpot [ended legacy private-app creation](https://developers.hubspot.com/changelog/legacy-private-app-creation-sunset) on September 28, 2026 for accounts created on or after that date, and on October 26, 2026 for older accounts. Existing legacy private apps continue to work, so the private app steps below are for finding and managing an app you already have.

For a new connection, create a [service key](https://developers.hubspot.com/docs/apps/developer-platform/build-apps/authentication/account-service-keys), which HubSpot recommends for new direct integrations, or use [HubSpot OAuth](/integrations/hubspot-setup). Sim calls HubSpot's REST APIs with a service key as a Bearer token, exactly as it does with a private app token.

## Create a service key [#creating-a-service-key]

Super admins and users with the **Developer tools access** permission can create service keys.

<Steps>
  <Step>
    In HubSpot, navigate to **Development**, then **Keys** → **Service keys**. In some accounts the page is under **Settings** → **Integrations** → **Service keys** instead.
  </Step>
  <Step>
    Click **Create service key** and give it a name (e.g. `sim-hubspot`)
  </Step>
  <Step>
    Click **Add new scope** and select the scopes your workflows need (see [Choose scopes](#2-choose-scopes)), then click **Create** and confirm
  </Step>
  <Step>
    Open the key, click **Show**, then **Copy**. Continue at [Add the key to Sim](#adding-the-private-app-token-to-sim)
  </Step>
</Steps>

A service key works only for REST API calls. If you turn on automatic rotation, HubSpot replaces the key every 3, 6, or 12 months and emails admins before the old key expires; paste the new key into the credential in Sim each time.

## Prerequisites for a private app [#prerequisites]

You need a HubSpot **super admin** to create the private app. Private apps can only be created and managed by super admins in the portal.

<Callout type="warn">
The token is tied to the super admin who created the private app. If that user is later removed from the portal (or its permissions change), some API calls start failing with `USER_DOES_NOT_HAVE_PERMISSIONS` — association calls are commonly reported. Create the app from an account you expect to keep, and rotate the token if the creator ever leaves.
</Callout>

## Set up the private app [#setting-up-the-private-app]

### 1. Create the private app [#1-create-the-private-app]

<Steps>
  <Step>
    In HubSpot, navigate to **Development** in the left sidebar, then **Legacy apps**

    Existing private apps are under **Development → Legacy apps**. Creation availability is described above. If you don't see **Development**, look for **Private Apps** under **Settings** → **Integrations** in older portals.
  </Step>
  <Step>
    Click **Create legacy app** in the top right, select **Private**, and give it a name (e.g. `sim-hubspot-bot`) and description
  </Step>
  <Step>
    Open the **Scopes** tab and select the scopes your workflows need (see the list below)
  </Step>
  <Step>
    Click **Create app**, confirm, and copy the access token from the app's **Auth** tab
  </Step>
</Steps>

### 2. Choose scopes [#2-choose-scopes]

Service keys and private apps use the same scope catalog as HubSpot OAuth apps. Grant only what your workflows use. The full set Sim's HubSpot tools can draw on is:

**CRM objects (read/write as needed):**
```
crm.objects.contacts.read
crm.objects.contacts.write
crm.objects.companies.read
crm.objects.companies.write
crm.objects.deals.read
crm.objects.deals.write
crm.objects.line_items.read
crm.objects.line_items.write
crm.objects.appointments.read
crm.objects.appointments.write
crm.objects.owners.read
crm.objects.users.read
crm.objects.marketing_events.read
crm.objects.quotes.read
crm.objects.carts.read
```

**Tickets, emails, and lists:**
```
tickets
sales-email-read
crm.lists.read
crm.lists.write
```

Ticket tools need `tickets`, email tools need `sales-email-read`, list tools need `crm.lists.*`, and each object type's tools need its `crm.objects.*` scope. Notes and association tools need the CRM object scopes of the records involved. A missing scope surfaces at run time as a `403` error with category `MISSING_SCOPES` naming the scopes required — widen the key's or app's scopes in HubSpot, save the change, and re-run the workflow. If the `403` persists, rotate the token and update the credential in Sim.

Sim's OAuth flow also requests an `oauth` scope — that one is OAuth-app-only and doesn't exist for private apps. You don't need it and can't grant it.

### 3. Copy the token [#3-copy-the-token]

The token looks like `pat-na1-…` (North America) or `pat-eu1-…` (EU data residency). Both work — Sim calls `api.hubapi.com`, which serves both regions.

<Callout type="warn">
The access token is bearer credentials for your entire portal, limited only by its scopes. Treat it like a password — do not commit it to source control or share it publicly. Sim encrypts the token at rest.
</Callout>

## Add the key to Sim [#adding-the-private-app-token-to-sim]

<Steps>
  <Step>
    Open **Integrations** from your workspace sidebar
  </Step>
  <Step>
    Search for "HubSpot" and open it, then click **Add to Sim** and choose **Add service key**
  </Step>
  <Step>
    Paste the service key or private app token into **Service key or private app token**, and optionally set a display name and description
  </Step>
  <Step>
    Click **Add service key**. Sim checks HubSpot’s token-info endpoint and, when that endpoint doesn't recognize the key, its Account Information API — if it fails, you'll see a specific error explaining what went wrong.
  </Step>
</Steps>

## Use the credential in workflows [#using-the-credential-in-workflows]

Add a HubSpot block or the HubSpot CRM Trigger to your workflow. In the credential dropdown, select the saved HubSpot credential. Configure the operation and its required fields. Service keys and private app tokens also work with the polling trigger. If the creating admin leaves or loses permissions, follow the account-management guidance above.

The block calls `api.hubapi.com` using the key — the same API requests used by the OAuth connection. Availability depends on the key's scopes and account access.

## Rotate the token [#rotating-the-token]

Service keys and private app tokens don't expire unless rotated, but HubSpot recommends rotating them every six months. From the service key's page, or the private app's Auth tab, you can:

- **Rotate and expire now**: the old key stops working immediately
- **Rotate and expire later**: the old key keeps working for 7 days while you migrate

Prefer the 7-day option: rotate in HubSpot, paste the new key into the credential in Sim, confirm your workflows run, and let the old key lapse.

## Handle permission failures

A successful connection does not prove access to every CRM operation. For HTTP `403` with `MISSING_SCOPES`, add the scopes named in the error, save the app’s scope changes, and retry. Account downgrades can also remove access to features even when the token string stays unchanged.

If the creating user is removed and calls return `USER_DOES_NOT_HAVE_PERMISSIONS`, have a super admin rotate the token and update Sim, or restore that user’s access where appropriate. See [HubSpot’s legacy private-app guidance](https://developers.hubspot.com/docs/apps/legacy-apps/private-apps/overview).
