---
title: Generic Secrets
description: Store shared or personal secrets for Build and Plan
---

Generic Secrets stores values that Build and Plan can use in code and requests. It uses the same [secrets editor as workspaces](/platform/credentials) and does not connect an external account or add searchable documents.

## Add the source

An organization admin opens **Settings → Sources → Add source → Generic Secrets** and chooses a mode:

| Mode | Manage values | Use in Build and Plan |
| --- | --- | --- |
| **Organization** | Admins open **Secrets** from the source in Settings. | Members with Build access use shared values. Members cannot open the editor to view them. |
| **Member** | Each person opens **Integrations → Generic Secrets → Manage secrets**. | Each person uses only their own values in the organization. |

Only the selected mode is active. To change it, select **Configure** on the source.

## Use a secret

1. Save a name and value in the editor.
2. Ask Build or Plan to run code that needs that secret.
3. The mode sees available names and mounts the names needed by `run_code` or `run_function` as environment variables. Code can use them in requests such as `curl` without putting values in the prompt.

In an organization conversation targeting a workspace, an organization secret takes precedence over a workspace secret with the same name. Member mode resolves the current member's values and cannot use another member's secrets.

Generic Secrets is available only in **Build** and **Plan**. Search mode, Search MCP, and Sim Search in Slack cannot mount these values. Workspace secrets remain a separate resource.

## Remove the source

Removing the source deletes its organization and member secrets. Review the confirmation before removing it.
