Sim Search helps you find and use information from your company's connected apps. Look up a document, ask a question across sources, catch up on a project, or turn what you find into a brief, update, or draft.

## Use Search

| You want to… | Start here |
| --- | --- |
| Find and browse documents | [Find content](/search/find-content): open **Search** in the organization sidebar. |
| Get an explanation or compare sources | [Ask questions](/search/ask-questions): open **Home** and choose **Search** conversation mode. |
| Understand a particular result | Open the result's **… → Summarize** menu, then ask follow-up questions. |
| Create a draft from your findings | [Draft from your sources](/search/ask-questions#draft-from-your-sources): ask for an update, email, FAQ, or presentation outline in the conversation. |
| Prepare for a meeting | [Combine Calendar and project sources](/search/ask-questions#prepare-for-a-meeting) into a brief with decisions and reading material. |

For example, ask “Why did the Atlas launch date change? Use the project documents in Confluence and Google Drive, and cite the sources.” Open the citations to check the evidence, then continue with “What does each owner need to do before launch?”

Search mode retrieves and reads information and drafts text in your conversation. It does not send the draft or change source records. You choose where to use the reviewed result.

Start with [Get started](/search/quickstart), then explore [Ask questions](/search/ask-questions) for more examples. [Connect your account](/search/connect-your-account) if your source requires a personal connection. The source setup below is for organization admins.

When enabled by your organization, [Sim Search in Slack](/search/slack#use-sim-search-in-slack) and [Search MCP](/search/mcp) let you search from other tools using the same retrieval and access rules.

## Add your first source

1. An organization admin opens **Settings → Sources → Add source** and chooses a provider.
2. Choose **Member accounts**, or a service mode supported by that provider. Save the source; service modes also require a connection and resource settings.
3. Each reader opens **Integrations** and connects their own provider account, including admins. GitLab uses configured project permissions instead of personal connections.
4. Search for a distinctive phrase in content that account can open. Read the result and follow its source link.

Adding a member source makes the integration available for members to connect. Provider app or deployment setup must be complete before authorization succeeds. [Connect your account](/search/connect-your-account) explains connection status and recovery.

## Choose a connection mode

| Mode | Admin setup | Search boundary |
| --- | --- | --- |
| **Member accounts** | Add the integration; no organization resource filters. | Content the connected member can access through the provider. |
| **Service account** | Select a service connection and its folders, labels, spaces, or documents. | Content readable by the member and the service connection, within the source's current settings. |
| **GitHub App** | Connect an installation and add each repository with **Add repository**. | Repositories allowed by both the installation and the member's GitHub account. |
| **GitLab service account** | Add each self-managed project with **Add project**. Use an administrator token, or a non-admin token with CSV permissions. | Content retrieved by the source token and authorized for the reader by current GitLab checks or saved CSV grants. No personal connection. |

A service source restricts resources; it does not grant access the member lacks. For example, a Gmail source limited to **INBOX** searches only allowed messages in the connected member's own mailbox. See [how INBOX filtering works](/search/gmail#how-inbox-filtering-works).

Open a provider in **Sources** to manage its connection and resource settings. Removing a source stops it from authorizing later Search requests. Connecting an account does not add resource selections or start indexing. Credential Groups separately share account connections with workflows.

Availability depends on deployment configuration and organization policy. Google Docs, Sheets, and Slides use the Drive source. Knowledge-base connectors do not automatically become Search sources.

## Access and freshness

Search checks current Sim membership, provider connections, and source settings on every request and document read. Admins follow the same reader rules as other members. GitLab administrator sources check permissions during the request; non-admin sources use saved CSV grants, which admins must update when access changes.

Provider search freshness, supported content, pagination, rate limits, and bounded permission checks affect coverage. An empty result does not prove content is absent. Follow returned continuation cursors or narrow the query when coverage is incomplete; there is no Search indexing job to retry.

To verify a service boundary, search for content inside and outside its configured scope. Repeat as a teammate with different access. After revoking provider access or updating GitLab CSV grants, repeat both search and read; provider changes must be reflected by the provider API.

Conversations remain private to their author. An external account connection does not grant Sim organization membership. Invite teammates through **Settings → Members** or your organization's SSO.

## Search and knowledge bases

Workspace knowledge bases ingest, chunk, and index documents. Their connectors, processing status, and access settings are separate from live Search sources.
